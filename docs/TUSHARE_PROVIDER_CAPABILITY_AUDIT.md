# Tushare 兼容供应商能力审计

审计日期：2026-08-10。该文件记录的是当前配置的主服务实际响应，不包含 Token、URL 或供应商密钥。

## 结论

- 供应商书面承诺的基础范围是 109 个 Tushare Pro 兼容接口；本地已逐项登记并允许通过受控入口调用。
- 在书面清单之外，`stk_auction_o`（开盘集合竞价）和 `stk_auction_c`（收盘集合竞价）均实际成功。平台现已建立 200 项比较库存，其中新增官方积分候选、13 个实时接口和 6 个离线分钟接口均与供应商合同事实分开显示。
- **主源不具备可用实时能力**：2026-08-10 连续竞价实测的股票、ETF、指数、申万和期货实时家族均未获得可用实时行；多数明确返回“接口未购买”，`rt_min` 还曾触发主源频控。主源只能作为低频/非实时回退，禁止进入盘中决策路径。
- **超级源已拆分为物理身份**：`tushare_super_get` 已实测 14 个接口，其中 12 个可完整满足当前受控查询；`ths_member` 仅为小板块有界访问，`stock_basic` 可访问但同日比主源少 9 个有效代码，必须用主源对账。大板块完整成员改走 `tushare_super_sdk` 单板块快照。实时仅覆盖 `rt_k`、`rt_min`、`rt_min_daily`。其余 ETF、指数、申万及期货实时接口未验证为当前数据或明确不可用，禁止标记为“全实时覆盖”。请求中的 `provider: "super"` 仅是兼容路由别名。

## City `rt_k` 降级（2026-08-13）

连续约 24 秒对三只股票采样时，City `rt_k` 的价格、累计量、累计额均未变化，且仅返回交易日、没有交易所分秒时间。因此它只能作为**延迟累计量价/盘口背景**，不再进入实时确认、价差否决或触发条件。盘中确认使用腾讯高频快照与 City `rt_min`（带分秒时间）；GET `rt_min` 作为补充交叉验证，GET `rt_k` 也不承担唯一确认职责。
- 单个接口成功只能证明当前权限、正确参数与该日期的数据可用；空结果不等于无权限（如停牌、港股通持仓、月线在指定条件下可能没有行）。

标的：`000636.SZ`（风华高科）；窗口：2026-08-03 至 2026-08-07；每次调用限定单标的、单周和最多 200 行。

其中 `suspend_d`、`hk_hold` 和 `monthly` 的指定条件返回 0 行，属于有效的空数据响应；并非授权失败。

## 操作边界

不对供应商做“全接口 × 全历史”的探测或下载。该行为既不能证明每个接口在所有日期必有数据，也会违反供应商的限流提醒。新增策略依赖时，应以一个小窗口、最小字段的单接口验收为准，并将结果保存在 `quant.fetch_runs` 与 `quant.tushare_raw_records`。官方扩展的真实双源结果见 [Tushare 官方扩展与双源能力矩阵](TUSHARE_OFFICIAL_CAPABILITY_MATRIX.md)。

如需供应商层面的保证，应要求其书面确认：接口清单、实时分钟/集合竞价的具体 API 名称、每接口限频/行数、历史分钟交付方式以及故障切换规则；特别不要把“15000 积分”自动理解为独立实时产品权限。

当前配置的超级源对专题数据的单独审计见 [超级源 SDK 代理能力审计](TUSHARE_SUPER_SDK_CAPABILITY_AUDIT.md)。
