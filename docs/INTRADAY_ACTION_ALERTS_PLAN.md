# 盘中买卖、加仓与做 T 提醒：实施与验收方案

日期：2026-09-23。状态：设计及本地实施；不是已经上线的能力。正式验收以文末实测记录为准，未通过时不发布。

## 目标与不变项

当前异动卡只说明行情变化，日线纪律不能当作盘中买点。本次补齐首次买入、加仓、减仓、退出、先买后卖旧仓、先卖后接回六类人工决策提醒；不连券商、不下单、不改推荐池、不降低原硬止损，不因仓位占比高要求减仓。用户已批准实施测试，只有总体真实验收通过才发布，否则本地留存。

复用唯一正式数据库、Longhu封装及现有飞书传输；不新设并行选股系统。模型只解释已验证事件，不生成可直接执行的价格、股数或成交事实。来源排名、推荐决策ID、持仓快照ID、计划版本与行情时点必须随每个事件保存。

## 六类动作及确认边界

| 类别 | 输入资格与条件 | 失效/数量约束 |
|---|---|---|
| 首次买入 | 当前正式推荐、有效结构计划；突破确认或回踩后重新站稳，分钟量能及同源板块确认 | 不以日线成交额门槛直接套盘中；超过追高上限或跌破失效位不买 |
| 加仓 | 已持仓，原假设及风险线有效；出现新的有效入场结构 | 不因低于成本机械否决，也不因亏损自动补仓；显式禁加仓、退出条件、现金不足或风险超预算均阻断 |
| 减仓 | 有明确失效/分歧规则，持仓与可卖数量可核实 | 不因集中度单独触发；强势上涨本身不是卖点 |
| 退出 | 原生效硬止损或时间失效确认 | 优先于加仓/做T；只给可卖范围，T+1锁定部分单列 |
| 先买后卖旧仓 | 有可卖旧仓及现金，先出现已确认回踩买点 | 第二腿只能由实际买入成交触发；不能把新买股当日可卖 |
| 先卖后接回 | 有可卖旧仓，出现明确冲高衰减及足够价差 | 第二腿需实际卖出成交；回补不能越过禁买/结构失效/风险边界 |

日线确认保留原语义，不更名为盘中确认。新增分钟规则须显式记录分钟口径、连续根数、量能基线、板块确认与版本。暂定工程规则属于待验证假设，不宣称胜率或最优参数。

## 组件与状态

新增小包 `app/intraday_actions/`，与原纪律模块组合而非覆盖：

1. `engine.py`：纯输入输出，六类动作、风险/费用/T+1/报价新鲜度、同分钟确认和冲突裁决；不访问数据库网络。
2. `repository.py` / `service.py`：读取当前正式范围及计划，组织点时上下文，持久化覆盖清单/事件/去重状态/做T成交确认，复用飞书可靠投递。
3. `renderer.py`：只展示中文名称、动作、证据时间、区间、数量依据、失效与风险；不输出内部变量、UUID或未经验证的模型推论。
4. 独立测试/回放入口：真实历史数据与合成分支测试分开，不把回放当实时；测试不写生产业务表、不自动发送历史提醒。

共同契约：`evaluate(context: dict) -> dict`，至少返回 `status`、`events`、`blockers`、`coverage`。context 含 `now/account_key/symbol/name/role`，`quote`、已完成 `minutes`、有效 `plan`、`account`、`market` 和可选 `t_episode`。engine所有缺字段都返回具名阻断，不猜值。详细字段由核心实现的contract与测试固定，集成方不得自行另造语义。

候选状态为等待→接近→确认→失效/过期；同一计划/同一动作只发送状态迁移，首次启动已满足的历史条件仅建立基线。冷却不能压制更高优先级退出。重启、失败重试不重复推送；重新入场必须有新计划或明确重置，不能每十分钟重复“可以买”。

做T状态为等待首腿→待实际成交→首腿部分/全部成交→等待回补或卖出旧仓→部分完成/完成/取消。提醒、点击已读、快照数量变化均不是成交证明。默认按已导入真实成交记录或用户明确成交回报确认；记录来源、成交价、数量、时点、幂等ID，允许部分成交，不复用同一成交支持两个episode。未确认首腿不发确定性第二腿指令；可显示条件观察。隔夜不自动冒充当日完成，单列遗留敞口。

## 账户、风险、费用

- 唯一账户 `citics-primary`。可用研究资金按用户约定总资产减股票市值；不把券商冻结挂单现金读数替代该口径，同时不能承诺订单真实购买力。
- 风险使用现有单只止损预算5%，数量按最不利允许买价计算；所有待确认买入提醒共享可分配资金，不能分别承诺可满额执行。
- 可卖以可信快照及已核实成交的时间顺序推导，未知变动则不给确定股数；新买当天不可卖，做T卖的是可卖旧仓。
- 佣金/最低收费/税费/滑点使用可溯源的账户成本配置，不用模型默认费率；缺失则做T净价差不可判定，不能发确定性套利建议。
- 买点数量为本次增量，不是总目标持仓；减仓数量不超过可卖量。当前风险线优先于摊低成本、做T回补或追价。

## 飞书与网页

沿用5秒报价/已完成分钟确认；每个已确认动作及时发送，不等待模型。接近条件默认工作台显示而非频繁通知。日内简报仍10:00、11:35、14:45，十分钟模型只解释真实变化。历史重复异动不额外跟发。

卡片首屏：股票与动作→当前价格及有效区间→数量或“待核对成交”→两三条确认依据→失效/追高上限→行情/账户时点。做T卡必须注明先后腿和未回补/未卖出风险。链接复用现有私群授权链接生成函数，不另存密钥。

覆盖清单逐股逐动作显示：可提醒/等待条件/缺计划/计划拒绝/持仓过期/成交未知/无可卖旧仓/成本缺失。持仓侧阻断不阻断推荐侧价格观察。状态接口不能只报循环存活为健康。

## 工作流、责任与发布闸门

阶段A：主agent制定契约，独立agent审查现有模块和风险，不照抄历史实现。
阶段B：核心规则与场景测试、持久化与运行时集成并行；各worker负责自己的文件，先测试后实现，不改生产。
阶段C：独立复核者审查双方差异；主agent做交叉集成、真实历史回放、异常及覆盖检查。问题返回原owner修复。
阶段D：冻结干净提交，留本地验收回执；仅所有必需门禁通过才用正式发布脚本。不得SkipTests/AllowDirty/IgnoreDeployWindow，不得手改current或重启共享服务绕过失败。

必需门禁：

1. 六类动作各有会触发与不应触发的真实语义测试；补仓不会绕过禁加仓，强势票不会只因涨幅/仓位被卖。
2. 真实历史逐时回放只用当时可用计划/报价，不用收盘后新计划证明早盘买点；没有样本的分支如实列未验证。
3. 开盘跳空、断线、旧报价、重复分钟、午休跨段、涨跌停无对手盘、缺板块、资金不足、费用不足、T+1、部分成交、同成交重复消费均正确处理。
4. 数据库事务/重启/发送失败重试/同事件幂等、独立风险退出不被做T吞掉，测试库实测。
5. 当前全部持仓及正式推荐逐只覆盖读回；质量拒绝必须定位，不放宽质量门或静默漏股。
6. 每类卡视觉/文本验收、中文无变量、动作与角色一致，授权测试卡不得冒充实盘。
7. 后端全套、相关架构测试、前端类型/构建、API合同、Git diff与密钥扫描通过；明确分开工程正确性与交易策略收益未验证。
8. 上线前本地真实供应商数据联通及隔离影子运行；休市不能冒充实时。如果真实盘中验收尚不可完成，维持本地，不自行部署一个未启用版本充当完成。

新增规则的历史表现不足不能宣称收益有效；发布只是人工辅助提醒，不给自动交易权限。

## 本地工作流及隔离边界

- 规则 worker：契约、六类动作、真实成交驱动的做T状态、故障回归。
- 编译 worker：冻结结构到独立分钟计划，保持原纪律语义；完成后与规则 worker交叉审查。
- 集成 worker：正式库只读输入、本地 SQLite 影子状态及发件箱、发送前复核、重启与幂等回归。
- 主 agent：计划、卡片表现层、发布验收判断、跨模块审查、全套回归与最终结论。

`ShadowRepository` 是可丢弃的本地测试存储，不是第二套正式数据库。没有被注册为后台循环，没有新增计划任务，没有真实飞书发送。正式 PostgreSQL adapter、生产循环接线及逐股计划覆盖尚未验收前，即使影子测试通过也不具备部署资格。

`intraday_actions.acceptance.release_decision` 用具名证据项整理发布阻断，不是已经接入生产发布脚本的门禁。不得把填写 `passed=true` 当测试；每一项必须有可复验产物。必须另外保留正式发布脚本全部既有检查。
