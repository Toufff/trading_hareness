## 2. 当前能得出的初步判断

### 分析师层

1. 观点整体偏多，尤其在 8/12、8/14、8/17 的科技、PCB、电子布、MLCC、半导体材料、光通信等主题上出现集中看多；但市场流向在 8/13 由 8/12 的净流入迅速切换到广泛流出，说明“主题中期逻辑”与“当天可交易方向”混在了一起。
2. 观点常同时包含“长期持有/底仓不动”和“盘中减仓做 T”。这不是一个二分类标签，必须拆成方向、动作、时间窗、仓位变化、触发条件和失效条件，否则会把“看多但建议减仓”错误算成看多预测。
3. 当前本地日线成熟结算仍不足：`analyst_opinion_outcomes` 的成熟日线独立事件为 0，主要状态仍是 `pending` 或 `unavailable`；但盘中同交易日结算已产生 36 个独立 `observation_id`、112 条 5/15/30/60 分钟窗口结果。现在可以对这些盘中结果做人工评判（按动作、窗口、方向收益、命中率、MFE/MAE），但样本仍不足以给出稳定 IC 或实时权重。
4. 分析师之间存在同日同主题的羊群和互相矛盾。评测必须同时报告“原始命中率”和“去相关后的有效样本数”，不能按消息条数给高频分析师更大权重。

### 当前可人工评判的成熟盘中 outcome

当前窗口已经存在可判定的盘中结果，不能再笼统写成“成熟 outcome 为 0”：

- 去重后为 36 个独立 `observation_id`、112 条 5/15/30/60 分钟结算行，全部来自杨宁的可用股票观察；同一观察的多个分钟窗口只算一个独立事件。
- `watch` 动作：5 分钟方向命中率 72.2%、方向收益 +0.140%；15 分钟 53.8%、+0.069%；30 分钟 58.3%、+0.305%；60 分钟 75.0%、+0.853%。这组小样本显示“观察后延续”在 30–60 分钟更有解释力。
- `avoid` 动作：5/15/30/60 分钟方向收益分别为 -0.137%、-0.175%、-0.295%、-0.229%，命中率分别为 22.2%、42.9%、33.3%、61.5%；均值为负且 MFE/MAE 不对称，暂不能把它当作稳定的反向交易信号。
- 合并 112 条窗口结果的方向命中率为 51.8%、平均方向收益 +0.052%，只说明已有人工复核素材，不足以证明分析师技能或调整实时权重。其余大部分盘中行因缺少同源、同交易日窗口标为 `unavailable`，不能当作失败样本。
- 安强作者 `stated_at` 回放另有 22 个独立动作、39 条成熟窗口结果（5/15/30/60 分钟）；它们严格使用作者声明时刻、仅用本地同源盘口，属于 `replay_only`，所以展示在人工评判区但不计入 36 个策略可用独立事件，也不进入实时门禁。

因此当前判断是：杨宁的 `watch` 盘中观点有初步、时长依赖的正向迹象；`avoid` 观点尚不稳定；安强、六子、郭一鸣、立伟、全能野人的日线 outcome 仍未成熟。系统已把这组人工可评判结果展示到前端，但自动晋级门禁仍按 60 个交易日/200 个独立事件执行。

### 市场层

1. 8/10、8/11、8/13 是资金流出或风险收缩日；8/12、8/17 是资金扩散日；8/14 和 8/21 是价格与资金出现背离的轮动日。
2. “资金由负转正 + 板块相对强度上升 + 龙头成交量确认”比单日净额更适合作为分析师观点的条件变量。
3. 8/10 的高股息、白酒、金属、黄金等流入与芯片、AIDC、CPO、5G、PCB 等流出并存，说明同一市场状态内存在结构轮动；市场级判断不能替代板块级判断。

以上是描述性结果，不是对任何分析师的投资评价，也不构成买卖建议。正式评价要等后续结算完成。

## 3. 评测对象和标签契约

每条分析师证据在进入评测前统一为一个不可变预测事件：

```text
prediction_id
analyst_id
source_kind                  # report/message
source_id + source_version + content_hash
received_at                  # 策略可用时间
stated_at                    # 原文时间，仅复盘证据
subject_type                 # market/sector/stock
subject_key                  # 审核映射后的稳定 ID
action                       # buy/add/hold/reduce/sell/watch/avoid/neutral
direction                    # -1/0/+1
horizon                     # 5m/15m/30m/60m/close/1d/3d/5d/20d
strength + explicitness
conditions + invalidation
extractor_version
```

主题必须通过审核别名和点时成员映射连接到板块，禁止用中文名称模糊 join。无法唯一映射的内容进入 `unmapped_evidence`，只展示，不进入评分。

## 4. 结算定义

### 4.1 市场观点

- 方向标签：指数相对前收/开盘/当时市场状态的未来变化。
- 短周期：收到后 5、15、30、60 分钟以及午收、收盘；只在当时存在可用行情时结算。
- 日级：次一交易日、3 日、5 日；用指数和全市场基准计算超额收益。
- 结构标签：`flow_expansion`、`flow_risk_off`、`mixed_rotation`、`flow_deterioration` 等，由当时可用的板块广度、净额变化和指数广度共同定义。

### 4.2 板块观点

- 板块收益：板块等权/流通市值加权相对市场超额收益。
- 资金确认：净额 z-score、正向概念比例、净额加速度、由负转正/由正转负、连续流入天数。
- 联动：板块龙头、涨停池、龙虎榜净额、板块成员的成交量/换手和相对强度。
- 结果分为“方向正确”“方向错误”“资金确认但价格未确认”“价格确认但资金背离”，避免只看涨跌。

### 4.3 个股观点

- 盘中动作使用收到时点的后续路径：MFE、MAE、先到目标还是先到止损、5/15/30/60 分钟和收盘收益。
- 日级动作使用不复权撮合价，研究特征使用统一的调整价视图；涨跌停、停牌、T+1 和交易成本单独建模。
- “持股/底仓”不是买入信号；“减仓做 T”拆成风险控制事件和方向预测事件。

## 5. 特征设计

### 分析师因子

- `analyst_direction`: 方向和动作分离。
- `analyst_strength`: 强度、确定性、目标/失效条件是否明确。
- `analyst_horizon`: 预测期限，短线与月线不混合。
- `analyst_freshness`: `received_at` 到市场快照的延迟。
- `analyst_revision`: 同一标的/主题的新旧观点变化。
- `analyst_consensus`: 去重后的分析师共识；同时记录有效分析师数和符号相关性。
- `analyst_independence`: 分析师独立性/来源类型，仅作为研究协变量，不自动提高权重。
- `analyst_coverage_quality`: 正文完整、时间证据、主题映射、抽取置信度和可交易报价覆盖。

### 市场与板块因子

- 指数收益、波动、成交额、上涨/下跌广度、涨停/跌停和破位比例。
- 板块净额、净额 z-score、正向比例、净额变化/加速度、流入流出转换。
- 板块相对强度、龙头相对强度、成员扩散度和“龙头先动—后排跟随”时差。
- 龙虎榜净买/净卖、上榜席位重复度、涨停封单/开板和换手结构。
- 数据质量：源延迟、缺口、跨源价差、成员映射完整度和是否使用了收盘后才可用的字段。

## 6. 评测框架

每位分析师、每种主题和每个期限至少输出：

- 覆盖率：预测数、可映射数、可结算数、不可用原因。
- 方向质量：precision、recall、balanced accuracy、方向收益。
- 概率质量：Brier score、log loss、可靠性曲线、校准误差；概率必须对应明确动作和期限。
- 经济质量：平均超额收益、胜率、盈亏比、MFE/MAE、最大回撤、换手和成本后收益。
- 稳定性：按交易日、市场状态、主题、时间段、分析师和样本新旧分组。
- 相关性：分析师观点符号相关、同主题重复、有效独立样本数。
- 延迟：`received_at` 到第一条可用行情/成交量/板块快照的秒数。

必须对比四个基线：市场状态基线、板块流向基线、价格/量能基线、等权分析师基线。联合模型只有在样本外超过基线时才有意义。

## 7. 完整实施阶段

### P0：远端同步和数据质量（1–2 天）

1. 修复已发现的 cursor 续页契约：续页只发 `cursor`，不要附带 `limit`。
2. 对远端 `409 cursor_stale` 实现有限重启：保留原始 `received_after`，清空 cursor，最多重启两次并记录版本变化。
3. 报告、消息分开限速；遇到 429 使用 `Retry-After`，不循环重试单条详情。
4. 记录每次远端同步的请求页、详情数、429/400/409、首尾 `received_at`、版本和水位；不保存 bearer。
5. 继续只导入远端提取文字和时间字段，不请求媒体。

验收：连续 10 轮同步无未解释 400；429 能退避；报告支路失败不阻断消息支路；同一消息重复导入不新增事实。

### P1：统一预测事件账本（3–5 天）

1. 复用 `remote_analyst_messages/reports → evidence → claims → opinions`，增加 append-only `analyst_prediction_events` 物化层。
2. 每个事件保存 source hash、extractor version、received/stated 时间、动作、方向、期限和映射质量。
3. 建立审核主题别名和点时成员连接；无法映射的证据显式降级。
4. 为安强等带正文时间的消息保留 `stated_at` 复盘索引，但禁止回写 `available_at`。

验收：任意评分都能反查原文 hash、版本、收到时间和抽取器版本；同一内容修订不会覆盖旧事实。

### P2：双时间尺度结算（1–2 周）

1. 增加 analyst action intraday outcomes：5/15/30/60 分钟、午收、收盘、MFE/MAE、先到目标/止损；收盘调度和盘后一键刷新已自动调用结算，路径指标限定同源、同交易日、入场到退出窗口。
2. 保留日级 1/3/5/20 日超额收益，并补齐指数/板块基准。
3. 结算使用点时可用数据；缺报价、停牌、涨跌停、T+1 明确为 `unavailable` 或 `not_tradeable`。
4. 修复 UTC/Asia-Shanghai 边界，所有日期使用交易所日期。

验收：同一 cutoff 重跑结果稳定；未来数据不能进入历史评测；缺数据不会被当作错误方向。

### P3：描述性评测和基线（1 周）

1. 生成两周研究报告：分析师卡片、观点时间线、市场状态叠图、板块流向曲线和证据覆盖矩阵。
2. 输出“观点—当时流向—后续结果”三联表，不把同日事后观点混成盘中可用信号。
3. 实现市场/板块/价格量能/等权四个基线和 ablation，先只做 `research_only`。
4. 把 8/10、8/11、8/12、8/13、8/14、8/17、8/21 标成不同市场状态，避免把不同 regime 混成一条胜率。

### P4：离线学习与概率校准（2–4 周）

1. 已实现无第三方依赖的 expanding Platt/logistic OOF 校准（含 embargo、Brier/log-loss/可靠性分箱）；当前仍因成熟日级事件不足返回 `insufficient_history`，只展示不生效。
2. 以 `analyst × horizon × subject_type × market_state` 分组收缩到等权先验；小样本只显示区间，不给单点高权重。
3. 用 fixed-share/Sleeping Experts 做离线组合，和等权、市场基线比较；在线实时链路不自我改阈值。
4. 只有满足 ≥60 个交易日簇、≥200 个成熟独立事件、每个关键 cohort ≥30 个样本，且样本外显著超过基线，才允许进入人工审批。
5. 5000 个成熟 outcome 之前，禁用条件子群、成对排序和复杂 prompt 演化；所有 challenger 保持 shadow。

### P5：前端和运行闭环（持续）

前端增加四个只读视图：

1. 分析师总览：覆盖、成熟度、延迟、质量门禁和当前权重状态。
2. 分析师时间线：每条观点的 `received_at/stated_at`、主题、动作、当时市场/板块流向。
3. 主题评测：流入流出曲线、板块相对强度、龙虎榜/涨停联动和观点分歧。
4. 结果卡：概率、校准区间、后续路径、MFE/MAE、不可用原因和证据链接。

前端必须标记：`research_only`、`insufficient_history`、`unavailable`、`mapping_incomplete`、`source_stale`；未晋级模型不能显示成买卖建议。

## 8. 统计与治理纪律

- 固定时间切分，使用 purged walk-forward + embargo；不能随机切分消息或重叠持有期。
- 多个分析师、主题、期限和模型同时试验时，使用 White Reality Check、Hansen SPA 或 Romano–Wolf 类多重检验，记录完整候选集合。
- 同日相同文本、转发和修订按 source hash/版本折叠；不能因为消息多就提高权重。
- 所有概率都必须带动作、期限和样本外校准指标；“看多概率”没有期限时不允许展示。
- 分析师因子最高只能作为小权重 context prior；市场风险门禁、T+1、停牌、涨跌停和组合暴露优先级更高。
- 任一同步故障、时间证据异常、成员映射缺口或跨源价差超阈值，自动把分析师因子降为 `research_only`。

## 11. 自动日报、周报与维护迭代

已落地自动化产物：

- `quant.analyst_market_reviews` 保存按交易日幂等的日报和按周幂等的周报，保留方法版本、周期、状态、完整评价投影、逐日观点净方向与市场涨跌、回归结果和治理边界。
- 收盘检查点生成日报；周五收盘在日报之后生成周报。任何失败不标记完成，下一轮检查仍可重试。
- 周报使用预先固定的描述性 OLS（正/负观点净方向、概念正向比例 → 市场平均涨跌），至少 8 个交易日才计算系数；不足时返回 `insufficient_history`，不补数据、不调实时策略。
- 前端自动加载日报/周报，双轴图显示“观点净方向 vs 市场均涨跌”，表格显示逐日市场状态和回归样本/斜率/相关系数/R²；也可手动重跑。

后续软件维护建议（不要求现在替换框架）：

1. 先把 `main.py` 的路由、仓储、调度和规则逐步拆成包，并以稳定的 Pydantic 请求/响应模型作为 Agent 的上下文契约；每个模块配一份短 `README`，记录输入、输出、时间口径、provider 边界和禁止的 live effect。
2. 为每条自动任务补“运行 ID → 输入快照 → 输出摘要 → 错误/重试 → 版本”链路和 `/status` 读模型；Agent 读取状态接口和最近失败日志即可定位，不必扫描 9000 行主文件。
3. 引入 OpenAPI 生成的 TypeScript 类型或共享 JSON Schema，避免前后端字段漂移；将数据库表迁移继续全部放在 Alembic，禁止启动时隐式破坏性 DDL。
4. 测试分三层：纯函数（回归/聚合/时间边界）、带临时 Postgres 的仓储契约、TestClient HTTP/鉴权冒烟；每次 provider 或策略改动先跑对应矩阵，再跑全量。
5. 框架保持 FastAPI + Vue 3 + ECharts + PostgreSQL + n8n：当前瓶颈是边界和可观测性，不是框架性能。等 `main.py` 拆分、连接池和任务锁稳定后，再评估 Celery/Temporal 等工作流框架，避免现在迁移引入第二套调度真源。
