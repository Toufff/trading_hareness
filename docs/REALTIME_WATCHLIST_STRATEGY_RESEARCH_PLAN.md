# 观察池实时策略强化计划

更新时间：2026-08-16。本文定义**研究、提醒和纸面组合**的升级路径；不授权自动下单，也不启动新的历史数据拉取或用历史数据重调盘中阈值。

## 0. 当前基线与不可突破的边界

### 运行态快照

- 当前 `quant` schema 为 12 GiB；研究总预算 40 GiB，热库预算 28 GiB，均低于告警门槛。高频非必要证据采集处于允许状态。
- 显式观察池 36 只。连续竞价正常 30 秒，重点窗口 10 秒；Super GET 交叉确认的启动节奏为 1 秒，盘口为腾讯批量请求。
- 飞书 outbox 可用，且仅对**观察池中已确认的个股信号**投递。自动挖掘、板块候选和涨停关联候选只进入前端研究台，不能暗中加入观察池。
- 主 Tushare 源没有已验证的实时能力；不能把它包装成实时行情。Super SDK 的股票 `rt_k` 只可作延迟累计上下文，Super GET 的已验证 `rt_k`/分钟接口才可参与交叉验证；腾讯为观察池批量行情，新浪为价格兜底，东财仅作分钟级板块资金流。
- “全板块 Top10”始终要求同源、点时成员映射完整；覆盖不足时返回覆盖率和阻断原因，绝不按中文名称猜板块归属。

此前已完成一次一年的日频数据任务；本计划不再重复拉取。为避免再次误触，`annual_daily_backfill` 命令将要求明确的 CLI 确认，且不会由服务或 n8n 自动触发。保留已有 raw 证据，不在未获批准时删除或重写它。

### 研究与实盘语义

1. 每个输入都必须有 `event_time`（市场事件时间，若供应商未给则为空）、`available_at`（策略首次可见时间）和 `ingested_at`（本服务接收时间）。回放按 `available_at` 稳定排序，不会在回放时请求供应商。
2. 分钟成交、主力资金流、五档快照不是逐笔委托簿；它们只能称为**订单流代理**，不能称为真 OFI。真 OFI 要有逐事件报价、成交和撤单增量。
3. 任何概率必须说明动作、期限和标签。例如入场应为：`未来 15 个交易分钟先触及目标收益而非先触发止损的条件概率`，而不是含糊的“上涨概率”。
4. 现有小样本的 Beta 收缩值只能显示为“历史条件基准率”。未获得时间外、独立交易日的校准证据前，飞书与前端不显示数值概率，更不能改变仓位或阈值。
5. A 股约束（T+1、100 股整数手、停牌、涨跌停、可卖数量）由单一现实模型统一供应给提醒、纸面组合和未来回放。不能执行的止损只能报告风险，不能伪装成已卖出。

## 1. 目标架构

```text
点时观察池 / 板块成员
          │
          ▼
不可变市场与分析师事件账本 ──► 版本化因子图 ──► 状态假设
  event / available / ingest          │              │
          │                            │              ▼
          └────────────────────────────┴────► Insight（方向、期限、失效条件）
                                                        │
                                        风险与数据质量门禁（只能降级或阻断）
                                                        │
                                                        ▼
                              飞书观察池提醒 / 前端研究候选 / 纸面组合建议
                                                        │
                                                        ▼
                         同一连续竞价时钟结算 ─► 回放 / 校准 / 晋级或退役
```

借鉴 LEAN 的 `Universe → Alpha/Insight → Portfolio Target → Risk → Execution` 职责切分：信号只表达预测；风险层只能削减、失效或阻断，不能因为“分数高”绕过 T+1、涨跌停或数据新鲜度门禁。[LEAN Algorithm Framework](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/alpha/key-concepts)

借鉴 Qlib，把原始、推理和训练处理分开，保留因子、数据集、标签、校准与策略版本；Qlib 的 `DataHandlerLP` 正是把 raw / infer / learn 分层，避免训练预处理污染盘中推理。[Qlib data layer](https://qlib.readthedocs.io/en/latest/component/data.html) 这也与其 PIT 原则一致：历史计算只能看到当时已经发布的版本。[Qlib PIT](https://qlib.readthedocs.io/en/stable/advanced/PIT.html)

## 2. 实时状态机：先补全生命周期，而不是堆指标

每个股票在一个互斥的 episode 中只有以下状态之一；状态迁移和原因码必须持久化。

| 状态 | 触发证据 | 提醒动作 | 机器可判失效 |
|---|---|---|---|
| `continuation_candidate` | 个股、板块与市场残差同向；站上 VWAP；同刻量能/广度改善；流动性未受压 | 仅研究台，待二次确认 | 回落 VWAP、量能衰减、板块广度转弱 |
| `reclaim_candidate` | 个股相对市场/板块的超跌残差极端，但板块和市场没有同步恶化；卖压代理衰竭，价格重新站回 VWAP | 观察或试探提示 | 再次跌破 VWAP 且 3/5 分钟动量、流入或同板块确认转负 |
| `confirmed_entry` | 同一策略在二次扫描中保持；跨源价格新鲜且一致；策略、市场、组合与可交易性门禁均通过 | 飞书“研究型入场提醒” | 写入 `valid_until`、价格/时间/板块三类失效条件 |
| `hold_or_reduce` | 已确认 insight 未失效；或上行中出现量价/板块/订单流背离 | 仅有持仓/可卖数量时提醒减仓或风险 | 动量转负、VWAP 失守、板块 leader 先转弱、风险门禁触发 |
| `exit_or_invalidated` | 明确失效、时间到期、纸面风险调整或数据质量失效 | 风险/减仓提醒；同步取消旧 insight | 新的独立 episode 才能重新入场 |
| `blocked` | 陈旧/冲突报价、映射不全、午休、停牌、涨跌停附近、T+1 不可卖、流动性不足或市场风险关闭 | 前端显示阻断原因，不推入场 | 条件恢复后重新评估 |

### 推荐因子（全部先作为证据或 shadow 特征）

- **相对而非绝对价格**：1/3/5/15 分钟个股残差收益，`r_stock − beta_market*r_market − beta_sector*r_sector`。beta 只用此前窗口估计；板块需点时精确成员映射。开盘、午后、尾盘各用自身历史时段分布标准化。
- **价格与量能**：VWAP 距离和斜率、首次突破/回踩承接、日内高低位置、同刻量能中位数惊喜、量价相关和区间 VWAP。绝不使用未收完的分钟线或当日收盘后才有的累计值。
- **板块扩散**：相对市场收益、成分股站上 VWAP 比例、上涨广度、同向资金流比例、leader 收益和目标股滞后；计算 leader 时排除目标股票自身。行业 leader–laggard 扩散先走本地滚动样本外检验，不固化为规则。
- **订单流与流动性代理**：五档深度、买卖盘不平衡、价差、封单单边状态、可比窗口 OFI 聚合、内外盘差分、深度变化。没有逐笔撤单/成交事件时不实现或宣称 VPIN、Kyle λ、真 OFI；VPIN 即便未来可算，也仅作压力 veto 的实验项。
- **市场状态**：5/30 分钟波动、板块横截面离散度、相关性、涨跌停距离、流动性压力和日内时段。高波动下只降低风险预算，不能自动推导出 alpha。
- **分析师上下文**：只用不可变 `received_at`/`available_at`；`stated_at` 可用于安强的动作复盘，但绝不替代策略当时的可得时间。分析师输出在统一 promotion registry 人工批准前始终为零 live 权重。

## 3. 分阶段执行与验收

### P0 — 证据、时钟、门禁（立即；不拉新历史）

1. 用连续竞价段和 90 秒报价容差结算 5m/15m/30m；跨午休、跨夜或缺少原窗口报价必须 `unavailable`，不能借用下午/次日首价。随后只基于本地证据重算现有 outcomes、attribution 和概率缓存。
2. 观察池报价写入/校验供应商时间、接收时间和最大年龄；Super GET 缺失或陈旧时，entry 降级为 watch，只有明确价差冲突才是硬阻断。全 A 横截面与观察池批量报价解耦，防止慢全 A 请求拖住核心扫描。
3. 补齐 B 浪反弹的完整生命周期：点时板块 peer 覆盖率、确认入场、VWAP/动量/流入和广度失效、T+1 可卖检查、时间退出。现有硬止损配置为空时，前端必须显示“未配置”，而非暗示保护已生效。
4. 修正归因标签：只有明确的 EAC setup 才可标作 EAC；共享研究字段不能污染策略族表现。
5. 历史数据 CLI 显式确认；持续展示 40 GiB 总预算、28 GiB 热库预算、最大表、保留期和高频采集门禁。先阻止增长，再讨论经批准的压缩归档；不静默删除 raw。

验收：100 个随机事件可从 signal 重建到输入的可得时间；所有成熟的短周期 outcome 都位于同一交易段和容差内；数据不新鲜时没有 `confirmed_entry`；同一输入的 episode/信号 hash 可重复。

### P1 — 版本化特征图与 episode（先 shadow）

1. 增加 `FactorSpec` 注册表：名称、版本、输入列、频率、预热天数、因果说明、质量门禁、训练/推理许可和弃用日期。不要引入通用字符串 DSL，先使用可测试的 Python 纯函数。
2. 将现有 VWAP、量能、板块共振、订单簿代理、B 浪和主升模型接入同一输入/输出契约；新因子只进入 evidence 与 shadow attribution。
3. 每个 `Insight` 记录 `horizon_key`、`valid_until`、`expected_return`（若有）、`invalidation_codes`、`factor_set_version`、`policy_version` 和数据质量旗标。静态极值在同一 episode 只提醒一次；只有条件清除后重现或指标实质升级才重发。
4. 前端展示候选的“推进因素 / 阻断因素 / 失效条件 / 数据新鲜度 / 覆盖率”；飞书仅展示观察池已确认信号，并附决策卡链接。

验收：同一市场事件序列的实时与本地重放输出完全一致；36 只观察股在 SLA 内全部轮到跨源确认；全 A 失败时观察池仍可评估，但流依赖的入场会降级。

### P2 — 确定性回放与 A 股现实模型（等待你重新授权使用/补历史）

1. 以已录制事件构造虚拟交易时钟，按 `available_at, source_sequence, event_id` 回放；严禁回放时外呼。
2. 将现有同一 `intraday_signal_policy` 与纯规则用于实时和回放；以“黄金交易日”对信号、冷却、episode、风险原因和结果哈希做回归。
3. 全面实现 A 股 T+1、涨跌停双侧、停牌、100 股整手、佣金/印花税、流动性分档滑点和不可成交。
4. 使用点时 universe、点时板块成员、新股剔除与除权一致的研究价格；不能用当前观察池回放来宣称无选择偏差。

验收：最少 60 个独立交易日、200 个独立成熟 episode，且每个市场状态/策略 cohort 至少 30 个；回放永远不读供应商；每个结果可复算。

### P3 — 条件概率、消融与多重检验（P2 通过后）

1. 训练/验证/测试按完整交易日 walk-forward 切分，标签窗口做 purge/embargo；绝不使用随机 KFold。
2. 基模型先比较正则化逻辑回归和轻量树，不上 LSTM/Transformer。按 `setup + regime + time bucket → strategy family + regime → family → global prior` 分层收缩。
3. 只用时间外 OOF 预测做 Sigmoid/Beta 校准；样本规模不足时不得使用等距分箱或 isotonic。校准要同时报告 Brier、log loss、可靠性图、ECE、独立日期和置信区间。scikit-learn 也明确要求校准器使用与基础模型训练集独立的数据，并提示 isotonic 在小样本容易过拟合。[scikit-learn probability calibration](https://scikit-learn.org/stable/modules/calibration.html)
4. 对所有窗口、阈值、策略和失败实验登记实验账本，并用按交易日分块的 SPA / Romano-Wolf 或等价程序控制多重检验。冻结最后一段未参与调参的样本。

验收：样本外悲观成本后期望值为正、Brier skill 优于基准率、多数滚动窗口同向、MFE/MAE/最大回撤均满足预先登记门槛。未通过时保持 `descriptive_only`。

### P4 — 纸面组合、分析师上下文和晋级（P3 后）

1. 将 `Insight` 和 `PortfolioTarget` 分离。概率只调整风险预算上限，不能线性变仓位或越过硬门禁；限制单票、板块、相关性簇、流动性冲击、换手、日损和组合回撤。
2. 分析师采用独立的日频与盘中 outcome 账本；消息同步健康、提取准确率、延迟、样本外方向价值、群体相关性都不过门禁时权重归零。所谓 “RL/evolve” 仅限离线 champion/challenger prompt lab：固定切分、人工金标、撤回审计、离线反事实评估和人工批准，禁止盘中在线自学习。
3. 晋级顺序固定为：`研究 → 回放 → 20 个交易日 shadow → 仅提醒 → 20 个交易日纸面组合 → 人工批准`。任一层出现覆盖/延迟/漂移/回撤熔断就退回 shadow。

## 4. 飞书提醒契约

提醒不是交易指令，固定输出五组可审计信息：

1. **何时、何种状态**：观测时间、交易段、episode、策略版本与有效期。
2. **推进原因**：仅列出确实满足的价格、量能、板块、订单流代理因素。
3. **阻断或降级**：数据陈旧、映射覆盖、来源冲突、T+1、涨跌停、组合预算等。
4. **失效条件**：可机器判定的价格/VWAP、动量、资金流/广度或时间条件。
5. **概率与置信度**：事件定义、期限、校准版本、保守区间、独立日期与样本数；不足时明确“暂不可估”。

示例（仅在 P3 校准后才可把数字称为概率）：

> 10:12 CST｜`confirmed_entry`｜15 分钟目标先达概率 61%（保守区间 53%–68%，246 episodes / 83 日）。推进：5 分钟残差回升、重新站回 VWAP、板块广度改善。失效：连续 3 分钟收盘跌回 VWAP 且资金流/广度转负。数据：腾讯 8 秒、Super GET 12 秒、点时映射 100%。

## 5. 明确不做的事

- 不把当前单日或当前观察池表现调成实时阈值。
- 不把供应商缓存的 `rt_k`、收盘资金流、当日最终 VWAP 或修订后的板块成员当成历史实时事实。
- 不按板块中文名称跨源 join，也不在覆盖不足时生成“完整 Top10”。
- 不让分析师文本直接加分、自动加仓或自动下单。
- 不删除 raw 证据来“腾空间”；只有明确批准后，才以可验证压缩归档和保留清单处理冷数据。

## 6. 本周的优先级

1. P0 本地 outcome 重算与时间窗审计；输出修正前后计数，不请求供应商。
2. B 浪 lifecycle/peer 覆盖及报价新鲜度测试；只 shadow，不改阈值。
3. FactorSpec、episode/insight 契约和前端证据展示。
4. 存储增长观测与历史 backfill 明确确认；继续保持 40 GiB 总预算。
5. 等你明确授权后再启动 P2 的历史/分钟回放与 P3 概率校准。

## 7. 研究依据与可移植边界

- 订单不平衡的预测性要与流动性、市场状态和时段一起使用，不能把分钟资金流伪装成逐笔 OFI；真正的 order-book event price impact 需要限价单、成交和撤单事件。[Cont, Kukanov & Stoikov](https://academic.oup.com/jfec/article-abstract/12/1/47/816163)
- 事件时间与接收/初始化时间分离、回测按本地可用时间稳定排序，是可复算和延迟诊断的前提。[NautilusTrader timestamps](https://nautilustrader.io/docs/latest/concepts/data/)
- 组合和风险层应与 alpha 分离；风险调整后仍要取消已失效 insight，避免旧信号反复驱动行为。[LEAN Insight Manager](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/insight-manager)

这些思想只迁移**契约和验收方法**，不把 Qlib/LEAN/vn.py/NautilusTrader 整体引擎或其非 A 股撮合假设嵌入盘中服务。
