# 盘中通知定位与降噪 v2（2026-09-22）

## 用户可见契约

| 类型 | 发送条件 | 第一屏 |
|---|---|---|
| 重要变化（个股/指数/板块） | 原有确定性规则确认新变化；采样与阈值不变 | 对象、区间涨跌、放缩量或缺失说明、多空状态、计划边界 |
| 持仓纪律 / 候选条件触发 | 原纪律规则确认，独立发送，不等待模型 | 已触发的具体线、确认依据、对应人工应对 |
| 条件更新 | 十分钟检查发现与当日已通知基线相比，原计划事实真的更新；模型亦判断有必要解释 | 哪个条件、前后值、对原条件的解释 |
| 阶段简报 | 10:00 早盘、11:35 午盘、14:45 尾盘 | 风险优先、市场概况、关键持仓/候选变化 |
| 服务异常 / 已恢复 | 自愈后仍失败或故障扩大；此前已成功通知的故障被实际验证恢复 | 对行情提醒/纪律提醒的影响，不展示技术字段 |

时间均为 Asia/Shanghai。简报使用两分钟启动窗，模型繁忙可在窗内启动；
缺少新鲜证据时不生成虚假报告。日历、数据新鲜度与覆盖率门槛不放宽。
10:00 / 11:35 / 14:45 按日期和类别使用持久化投递键，重启也不重复排队；
未成功生成时可在窗内间隔至少 60 秒重试一次。发送失败沿用既有有界 outbox 重试。
启动窗不保证分钟整点立即送达，也不在窗外追补旧盘面。

09:25 / 09:32 自检继续后台运行，正常、跳过以及未通知过的自动恢复均静默。
故障通知成功后，状态存入 `G:/StockPlatform/logs/runtime/opening-guard-notification.json`，
同一故障去重、新增失败项才再次通知。只有此前故障检查项全部通过，才通知一次恢复；
盘前检查不能把尚未验证的开盘行情故障称作恢复。发送失败不推进已通知状态。
`--as-of` 历史/手工模拟不发送通知，也不推进通知状态。恢复检查仍是已有两个任务时点，
本次没有新增全天运维监控任务；不能宣称故障恢复后会即时主动通知。

## 去重与模型边界

- 移除普通异动/纪律事件之后的 45 秒 Codex 跟随调用；确定性证据不再跟一张模型复述卡。
- 十分钟轮询仍在，但仅价格、量能、多空类别变化不会再启动模型。没有已通知基线时，
  不编造“原计划发生变化”；先由阶段简报建立当日基线。
- 可触发条件更新的字段见 `notice_policy.CONDITION_LABELS`：纪律/候选条件、计划阶段、
  持仓数量/可卖数量等。价格变动引起的市值与仓位百分比不是条件更新。
- 这不是额外的模型择时链路：行情变化由确定性卡承担，纪律是否触发由纪律规则承担。
  模型不得更改原计划、创造价格线、用委比投票或把候选当持仓。
- 条件更新幂等键是日期 + 代码/条件状态/上次已通知回执指纹，换措辞或换模型不产生第二条；
  同日真实 A→B→A→B 条件往返仍可分别通知，不因曾到过 B 就永久压制。
- 发送个股下跌卡前，查询同账户、同股、相邻 90 秒的止损/移动/时间纪律事件。
  **只有对应纪律卡已经发成功**，才将尚未发送的普通下跌卡记为 disabled /
  covered_by_discipline。未发送成功的纪律卡不覆盖价格告警，避免吞掉用户尚未看见的风险。
- 不压制其他股票、其他账户、候选、上涨或止盈事件。不能撤回已经发出的普通卡，
  也不推迟后发生的紧急纪律卡来凑“一条消息”；两条独立链路存在这个明确的竞态边界。
- 个股与行业缺少已核验映射时，不硬拼为板块共振；本次没有新增跨股聚合规则。

## 展示约定

- 红色表达紧急风险，不用来表示上涨；普通关注橙色，恢复/条件更新/常规简报蓝色。
- 个股卡标题直接显示对象与变化；首屏保留明确时间区间、涨跌和量能。
- 3/5 分钟触发不能藏在平静的最后一分钟后面；完整 1/3/5 分钟证据折叠。
- 委比、内外盘分类差、单位成交额价格响应在证据层，缺失值不补零，不合成任意总分。
- 阶段简报风险不折叠，不再拿第一只持仓动作当整个账户指令。
- 无新增类别/计划变化的逐股条目默认不再展开；未列出不代表停止监控。
- 简单条件显示前后值；复杂结构指向工作台，不把内部 JSON 原样发给用户。
- 模型来源放页脚；按钮诚实标为“打开决策工作台”，不冒充已实现的个股深链。
