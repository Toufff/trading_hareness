# 外部量化数据源与研究方法路线

调研日期：2026-08-09。本文把外部数据按授权、可得时点和用途分层；不是把第三方网页接口当作生产交易数据的许可。

## 已落地的基线

| 层级 | 已接入来源 | 当前用途 | 决策状态 |
|---|---|---|---|
| 授权市场数据 | Tushare 兼容主源、超级 SDK 源、REST 备用源 | 日线、财务、资金流、筹码、板块、涨停、实时家族 | 按 API 能力和质量门禁逐项决定 |
| 免费交叉校验 | 东方财富、腾讯财经、新浪财经、Baostock、巨潮资讯 | 个股日线/报价的独立核验，官方公告事件存证 | 研究证据；未授权实时快照和免费公告不单独进入推荐 |
| 分析师证据 | 远端报告归档 | 可追溯观点、时点和评分卡 | 只有已审核映射进入研究 |
| 板块扫描 | `moneyflow_cnt_ths`、`limit_cpt_list`、`ths_member`、`limit_list_ths` | 概念净流入、强度、成分-涨停交集 | 仅候选扫描，不直接下单 |

概念候选的严格规则是：对同一交易日，板块成分中的股票代码必须等于同花顺涨停池中的股票代码。`lead_stock`、涨停原因和概念名称仅用于展示，不能代替该交集。成分响应触发本地 3,000 行上限时，结果必须保留 `partial`，不得被当作完整板块。

## 2026-08-09 执行约束

历史 3-5 年 A 股数据先不做全量下载。服务新增 `/api/v1/data-readiness/history-estimate`，默认按当前 `all_a` 股票池、244 个交易日/年和现有 raw 样本行宽估算 3 年日频与高价值特色数据的容量；分钟数据只有显式 `include_minute=true` 时才进入估算，并继续标记为 `offline_only`。

单票研究优先采用“查询时按需补齐”。`POST /api/v1/stocks/{symbol}/study` 会在 45 天在线安全窗口内为该股票补齐 P0/P1 证据：日线、每日估值、涨跌停、东财主力/散户资金、复权因子、普通/同花顺资金流、筹码胜率、筹码分布和专业技术因子；同时保留腾讯/新浪/Baostock/巨潮等免费或公开源作为交叉验证证据。返回体中的 `on_demand_readiness` 是单票窗口状态，不受全市场 coverage 阻塞。

研究总览现在同时展示：

- 当前日线区间、全截面天数、最大单日股票数、分钟覆盖股票数。
- 3 年 P0/P1 日频数据估算容量和分数据集行数。
- `fetch_runs` 中运行中与超过 90 分钟的陈旧任务数量。

个股研究页现在同时展示：

- 单票 P0/P1 按需补齐状态、阻塞项、窗口行数和最新日期。
- 最新涨跌停、复权因子、估值、主力/散户资金、筹码胜率、筹码分布和专业技术因子。
- 授权源、超级源与免费交叉验证源的逐项执行结果。

陈旧任务不再靠手工改表处理。`POST /api/v1/operations/fetch-runs/reconcile-stale` 会把超过阈值仍处于 `running` 的任务标记为 `failed` 或 `blocked`，并保留错误分类 `stale_running_reconciled`。这只修复运行账本状态，不会重新拉取历史数据。

## 可补充的数据源

| 优先级 | 来源/类别 | 可新增数据 | 接入方式与边界 |
|---|---|---|---|
| P0 | 上交所、深交所、巨潮资讯官方披露 | 公告、定期报告、问询/回复、停复牌、回购、股东变动 | 做下载清单、公告发布时间和文件哈希；公告文本/事件只在 `available_at` 之后可用 |
| P0 | 中证指数、国证指数/交易所指数 | 指数成分、权重、调样和行业分类 | 保存每次成分调整的有效日和公告日，生成无幸存者偏差的历史股票池 |
| P1 | 现有 Tushare 主/超级源 | 融资融券、北向、龙虎榜、机构调研、盈利预测、行业/概念资金流、筹码和专业技术因子 | 继续 raw-first；先完成字段口径、覆盖率和可得时点测试，再进入 canonical 特征 |
| P1 | CSMAR、Wind、Choice、Ricequant、JoinQuant 等商业授权源 | 历史 PIT 财务版本、分析师一致预期/修正、基金持仓、宏观和衍生品 | 仅在获得书面授权后接入；以数据合同记录许可、字段、延迟、修订和保留期限 |
| P2 | AkShare | 多个公开站点的便捷读取层 | 它是聚合库而非独立权威源；仅作为可替换的 research connector，每条数据仍须标明实际站点与采集时间 |
| P2 | 公共新闻/互动平台/社媒 | 事件、情绪、主题扩散 | 先做来源许可、去重、发布时间、实体映射和漂移监控；不能以页面抓取替代持牌资讯数据 |

中证/国证的分类与成分数据能补足“板块概念”和指数暴露之间的稳定基准。国证的 CICS 分类是面向 A/B 股的规则分类体系；因此应独立于同花顺、东财等主题目录保存，不能把不同口径的板块直接合并为一个标签。<https://www.cnindex.com.cn/eng/analytics/standards/index.html?act_menu=3>

CSMAR 覆盖中国市场的行情、基本面、分析师预测、股东、衍生品和宏观等类别，适合作为商业 PIT 补充，但当前未配置其授权，不能假定可调用。<https://www.csmar.com/en/>

AkShare 的官方数据字典表明其覆盖面很广，但它汇聚上游站点数据；生产层必须保留上游名称和许可判断，而不是将 `akshare` 当成最终来源。<https://akshare.akfamily.xyz/data/index.html>

### AkShare 适配结论

AkShare 当前可作为“公开源聚合补充层”接入，但不能替代主 Tushare 源、超级源或未来商业授权源。项目本身是 MIT 许可的 Python 库，当前锁定版本为 1.18.93，要求 Python 3.9+；但其数据声明明确定位为学术研究和参考用途，并提示部分接口可能因不可控因素被移除。因此接入时必须把 `akshare` 拆成 `provider_key='akshare'` 和真实 `upstream_site` 两层 provenance，不得把网页聚合结果直接标记为授权生产数据。

当前 `quant-research` 镜像已安装 `akshare==1.18.93`，连接器仍受 `AKSHARE_ENABLED` 控制。导入失败、字段漂移或上游限流必须降级为交叉验证失败，不能阻塞主源/super 的单票按需补齐。完整缺口矩阵和新增补充包见 [AKShare 能力缺口与互补接入分析](AKSHARE_CAPABILITY_GAP_ANALYSIS.md)。

优先可扩展的数据：

| 优先级 | AkShare 能力 | 对本平台的新增价值 | 入库与决策边界 |
|---|---|---|---|
| P1 | 交易所市场总貌，如 `stock_sse_summary` | 补充收盘后市场宽度、流通市值和交易所级别统计 | 只作为市场状态层参考；当前交易日需收盘后才可用 |
| P1 | 东财龙虎榜，如 `stock_lhb_detail_em` | 补充游资/机构博弈、上榜原因和榜后表现 | 事件源，按上榜日和发布时间入库；不能盘中提前使用 |
| P1 | 涨停/强势股池，如 `stock_zt_pool_strong_em` | 与当前概念资金流和涨停池交叉验证，增强情绪周期/赚钱效应 | 近期数据、网页源，做候选扫描，不单独触发推荐 |
| P1 | 限售解禁、股本变动、机构持仓等 Eastmoney/CNInfo 包装接口 | 补充事件风险、流通盘变化和筹码供给压力 | 事件/解释层，必须保留公告日、变动日和上游站点 |
| P2 | 宏观、利率、商品、期货、期权、外汇、债券、基金等大类数据 | 构建市场状态和风格暴露，如利率、商品价格、期权波动率 | 先做日频状态变量，不进入股票级 P0 门禁 |
| P2 | 技术选股榜单/异动榜/热榜 | 给前端增加“公开热度/异动观察” | 只做展示和人工复核，不作为事实标签 |

暂不优先使用 AkShare 的场景：

- 主源/super 已稳定提供的单票日线、估值、涨跌停、资金流、筹码和技术因子，不用 AkShare 覆盖。
- 需要书面授权、稳定 SLA 或可追溯 PIT 修订的数据，如财务版本、分析师一致预期、基金持仓历史和可交易实时行情。
- 大规模 3-5 年历史回填。AkShare 更适合按需补充或低频事件/状态源，不适合替代离线历史文件和授权源。

3. 新增 `POST /api/v1/providers/akshare/probe` 和前端代理 `/api/research/providers/akshare/probe`。单次 probe 对龙虎榜最多入库 100 条、强势股池最多入库 200 条。

## 研究框架的适配

### 1. 数据与时点

每一条可建模数据至少保留：`source`、`provider_key`、`observed_at`、`available_at`、`effective_at`、请求/文件哈希、字段版本和修订版本。财务报表、指数成分、公告和分析师预期必须按“当时已发布的版本”取值，而不能用今天修订后的值回填历史。

Qlib 的 PIT 设计正是为避免用未来修订数据回测历史；其文档明确说明，若只使用最新版财务数据会发生数据泄漏。Qlib 也支持中国市场配置，但其示例下载数据并非高质量生产数据，因此本项目只向它导出已验证的数据快照。<https://qlib.readthedocs.io/en/stable/advanced/PIT.html> <https://github.com/microsoft/qlib/blob/main/docs/start/initialization.rst>

### 2. 三层信号，而非单一总分

1. **市场状态层**：宽度、指数趋势、行业/概念资金流、风险偏好、涨停/跌停家数、成交额变化。它决定仓位上限和允许的策略类型。
2. **板块扫描层**：概念/行业净流入、动量、涨停强度、成分覆盖率和板块拥挤度。它只产出候选板块与证据。
3. **个股与组合层**：在候选板块内评估趋势、量价、主力/散户流、筹码成本、财务质量、盈利预期修正、公告事件及分析师证据；之后才做行业中性、流动性、集中度、T+1、涨跌停和成本约束的组合优化。

当前的“概念资金流 -> 概念成员 ∩ 涨停池 -> 个股多源技术研究”已实现第 2 层到第 3 层的可追溯链路。它不是未来收益预测，也不将涨停原因文本作为事实标签。

当前新增的“一键板块研究”会按同一交易日刷新概念资金流、涨停强度、概念成分与涨停池交集，再对候选股执行个股研究并补充巨潮公告。免费公告只作为事件风险和解释上下文，默认 `decision_eligible=false`。

### 3. 因子与事件研究

先使用可解释的日频基线：动量/反转、波动率、流动性、估值、质量、盈利预期、资金流、筹码和板块相对强度。每个因子按日横截面 winsorize、标准化，并按行业/市值中性化；评价输出至少包括 IC/Rank IC、分层收益、换手、覆盖率、缺失率、容量和成本后收益。

事件类信号（公告、业绩预告、调研、回购、股东变动、龙虎榜）必须以发布时间对齐，并和日线/分钟线的可用时点分开。聚宽的防未来数据规则同样区分盘中可取字段、盘后才产生的字段和披露日期，说明这一层不能只按交易日期存储。<https://www.joinquant.com/community/post/detailMobile?postId=23804>

Ricequant 的因子工具将因子计算、IC、分组和因子收益检验作为独立环节；其回测在 `before_trading` 与每个 bar 的事件处理中区分信号与订单，和本项目的盘前/午盘/收盘工作流一致。<https://www.ricequant.com/doc/rqfactor/manual/index-rqfactor> <https://www.ricequant.com/doc/quant/backtest.html>

### 4. 回测与训练硬门槛

- 使用滚动 walk-forward；训练、验证、测试按时间切分。
- 标签窗口会重叠时采用 purged/embargo split。`mlfinlab` 的 `PurgedKFold` 删除与测试标签区间重叠的训练样本，并支持 embargo。<https://github.com/hudson-and-thames/mlfinlab/blob/master/mlfinlab/cross_validation/cross_validation.py>
- A 股回测必须模拟 T+1、停牌、涨跌停无法成交、集合竞价/连续竞价时段、佣金印花税、滑点、冲击成本及成交量参与率。
- 任何模型先和等权、指数、简单多因子规则基线比较；仅有收益而没有成本后收益、回撤、换手和不同市场状态分解的实验不能注册为候选模型。
- LLM/分析师文本只产出带置信度的事件特征和可追溯引用，不能直接产生买卖指令。

LEAN 的设计也将数据源、选股、组合、成交和滑点模型拆分，并支持多数据源与自定义数据；这与本服务的 provider/provenance 层和离线实验层相符，但当前不应替换已经实现的 A 股约束回测。<https://www.lean.io/lean/docs> <https://www.quantconnect.com/docs/v2/lean-cli/live-trading/data-providers>

## 实施顺序

1. **运行账本与入口稳定**：修复 n8n/Feishu 失败链路，定期对账陈旧 `fetch_runs`，任何入口失败必须有可见状态。
2. **按需补齐优先**：查询某只股票时先在 45 天窗口内补齐 P0/P1 单票证据，并把 `on_demand_readiness` 展示给前端；3/5 年历史只做容量估算和离线方案，不默认下载。
3. **数据质量与 PIT**：为财务、公告、指数调样和分析师预期增加 `available_at`/修订版本/覆盖率门禁；把板块成员批次完成度展示到候选表。
4. **官方结构化数据**：巨潮公告清单已先接入为免费事件存证；中证/国证成分权重仍待可用授权或稳定官方下载路径确认，先不接商业付费源。
5. **特征合同**：将通过质量门禁的行业资金流、概念候选、筹码、预期修正和事件数据写成版本化 feature contract，并扩展因子实验台。
6. **离线实验**：从不可变快照导出 Qlib 格式，先跑 LightGBM/线性基线和 walk-forward，再尝试时序模型或 GPU 训练。
7. **纸面组合**：仅在连续多个样本外窗口、成本后表现和风险门槛满足时，启用纸面组合监控；生产页面继续仅展示研究结论。

## 不应做的事

- 不以免费网页报价覆盖或静默修正授权源的历史数据。
- 不把概念名称、涨停原因或模型生成文本当作成分关系。
- 不在盘中用收盘后才发布的龙虎榜、财报、行业汇总或完整日线生成当日信号。
- 不在缺少历史退市股票、复权、涨跌停、停牌和费用数据时训练 GPU 模型或宣称可实盘。
