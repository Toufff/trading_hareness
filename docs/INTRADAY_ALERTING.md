# 盘中异常信号与提醒

这是一个“提醒和留痕”链路，不会提交订单，也不会把研究候选自动变成买卖指令。

盘中消息是研究线索而非已验证交易信号：现有阈值尚未完成足量分钟回放验证，消息中的证据用于人工复核，不应用作自动下单依据。

## 数据与边界

- 腾讯全 A 即时行情：服务内每 30 秒拉一次横截面，只读取观察/持仓池的价格、涨跌、量比、换手和公开主力净流入指标。
- 超级 Tushare 实时 GET：每次最多复核 4 个优先标的的 `rt_min`，保留原始分钟线证据；失败不会用旧分钟线冒充实时数据。
- 东财板块资金流：服务内循环每 5 分钟生成并推送行业/概念流入、流出快报；未放进 30 秒单标的扫描以避免重复全市场请求。
- 同花顺、龙虎榜、巨潮公告、分析师观点：均按可得性写入研究/收盘背景；龙虎榜与收盘后事件绝不进入同日盘中触发条件。
- 新华财经：必须配置已授权的 API 合同、认证方式和字段契约后才会启用，系统不会猜测接口。

## 触发规则（v1）

- 硬止损：仅当标的被标为可卖持仓、开启退出提醒且配置了 `hard_stop` 时，价格触及止损立即确认。
- 入场条件：无可卖持仓，涨幅 1%–6.5%、量比至少 1.8、换手至少 2%、公开主力净流入为正，且价格高于上一扫描；必须连续两次满足（5 分钟窗口）才确认。
- 风险减仓：有持仓、较成本跌至少 3%、量比至少 1.5、公开主力净流入为负；同样需要二次确认。
- 异常量能：量比至少 2.5、换手至少 5%；作为观察提醒，需要二次确认。
- 大笔买卖：用同一时刻腾讯全 A 公开主力流指标的前 1% / 后 1% 分位识别，且量比至少 1.5；不依赖未经验证的绝对金额单位，仍要求二次确认。
- 异常拉升：日内涨幅至少 6%、换手至少 12%、公开主力流位于全 A 前 5% 时产生“观察”信号，即使量比尚未跟上；它永远不是追涨买入指令，仍要求下一个 30 秒周期确认。
- 板块共振候选（显式 opt-in）：观察标的需在 1 分钟上涨至少 0.75%、3 分钟上涨 1.5%–4.5%、当分钟量达到此前 20 分钟中位数的 3 倍、价格位于当日 VWAP 上方但不超过 5.5%；同时至少 2 只已配置同板块独立成分出现 `1 分钟 >=0.5% + 3 分钟 >=0.8% + 分钟量 >=1.8 倍`。独立成分确认可替代第二次时间确认，但日涨超过 6.5% 后一律拒绝追涨。该信号标为实验性人工复核候选，不连接订单。
- 龙头首动预警（同一 opt-in）：若板块尚未确认，但标的 1 分钟上涨至少 0.8%、分钟量达到此前 20 分钟中位数 4 倍、日涨仍低于 5%，先发等待确认的观察信号；连续两个 30 秒采样成立后提醒。它不是 buy 候选，只有后续满足上面的独立板块共振条件才升级。
- 日线因子：本地历史足够时附加 MA5/MA20 趋势、RSI14、20 日波动和 20 日量比；数据不足会明确标记，不参与伪精确打分。

任何已发送的同一信号在 10 分钟内会抑制重复消息；同一标的的 `watch` 类信号也共享该冷却期，避免公开源字段切换造成刷屏。`entry`、`reduce`、`exit` 或更高严重度不会被普通观察提醒压掉。所有扫描、行情、条件、信号状态与投递结果都写入 `quant` schema，便于复盘。

## 启用顺序

1. 配置观察/持仓池。填写 `entry_price` 即标记为已持仓；`available_quantity` 仅表示当前确认可卖的数量，可暂时留为 `0`（例如未登记股数或受 T+1 约束）。两者都不会连接券商或自动下单。

   若需要板块共振策略，必须在单一标的的 `metadata` 中显式配置一个有来源依据、数量受限的同板块篮子：

```json
{
  "surge_strategy": {
    "enabled": true,
    "sector_label": "同花顺钨",
    "peer_symbols": ["002378.SZ", "000657.SZ", "600549.SH"]
  }
}
```

   服务每轮最多为这类策略拉取 12 个腾讯分钟序列，最多 4 路并发；不会把全市场分钟线扫描塞进 30 秒主链路。

   每次新建或更新观察池条目，服务会自动拉取 45 个自然日窗口（通常覆盖最近约 30 个交易日）的 Tushare 日线、每日基础指标、Tushare 个股资金流和东财个股资金流，并写入一份因子快照。快照包括 MA5/MA20、RSI14、20 日波动和 20 日量比；少于 21 根有效日线时，快照会明确标记 `insufficient_history`，不开放因子判断。

```bash
curl -X PUT http://127.0.0.1:5681/api/v1/intraday/watchlists/600176.SH \
  -H 'content-type: application/json' \
  -d '{"symbol":"600176.SH","label":"中国巨石","available_quantity":0,"alert_on_entry":true,"alert_on_exit":true}'
```

2. 若要启用飞书推送，在私有环境变量中同时设置：

```dotenv
QUANT_ALERT_WEBHOOK_TOKEN=<随机长值，两个服务使用同一值>
FEISHU_ALERT_RECEIVE_ID=<明确的群 chat_id 或用户 id>
FEISHU_ALERT_RECEIVE_ID_TYPE=chat_id
```

未设置接收目标时，扫描和信号仍会落库，但投递状态为 `disabled`，不会向任何群或用户发送。

若研究台有一个飞书客户端可访问的 HTTPS 地址，可额外设置：

```dotenv
QUANT_DASHBOARD_PUBLIC_URL=https://research.example.com
```

确认信号将附带该标的的决策卡链接；未配置时系统明确提示在本地研究台打开，不会伪造 `localhost` 链接。

3. 运行扫描或由 n8n 调度：

```bash
curl -X POST http://127.0.0.1:5681/api/v1/intraday/scan \
  -H 'content-type: application/json' -d '{"realtime_validation_limit":4}'
curl http://127.0.0.1:5681/api/v1/intraday/scans/latest
```

`INTRADAY_SCAN_INTERVAL_SECONDS=30` 启用服务内连续竞价 30 秒观察池扫描。盘中扫描与五分钟板块快报均由服务内循环单点投递；旧 n8n 盘中定时工作流已停用，避免重复消息。交易时段、周末和本地交易日历均由服务端再次门禁，调度误触发不会请求实时源。

## 投递可靠性与日终摘要

- 每条确认信号先写入投递记录，再调用飞书。失败的文本会保存在本地 outbox，连续竞价的下一轮扫描最多重试 3 次；成功送达后才进入冷却计数。网络请求结果不确定时遵循至少一次投递语义，人工看到重复消息应以信号观测时间和决策卡证据为准。
- 信号消息包含上海时区的**观测时间**，不是发送时间；因此即使二次确认或网络延迟，也能判断线索新鲜度。
- 服务状态页会展示飞书最近投递、待重试数和连续失败数。连续失败达到 3 次时标为 `out_of_band_attention_required`；它不会尝试用同一条已失败的飞书通道给自己告警，需通过研究台/容器监控处理。
- `DAILY_SUMMARY_AUTOMATION_ENABLED=true`（默认）时，SSE 开市日的 19:15–19:30 产生并投递一条日终研究摘要。摘要只读取已落库的盘中信号、结算、盘后候选和数据门禁；失败至多重试 3 次，不重新请求市场源。它刻意不展示小样本胜率，也不把盘后候选逐条刷屏。
