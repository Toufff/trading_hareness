# 观察池实时策略：研究、挖掘与晋级协议

日期：2026-08-16（Asia/Shanghai）  
状态：**设计冻结，研究优先**。不自动下单；不拉取历史数据；不在实时样本不足时修改现有阈值或把分数包装成概率。

本文补充 `WATCHLIST_REALTIME_STRATEGY_EVOLUTION_PLAN_20260816.md`：前者规定工程与治理边界，本文规定如何从观察池、板块、龙虎榜、盘口代理和分析师文字中挖掘可验证的实时策略。

## 1. 决策

不引入完整 Qlib、LEAN、NautilusTrader 或 vn.py 引擎。现有服务已具备更适合当前范围的基础：点时证据链、纯规则、`policy_gate`、episode、纸面组合、投递 outbox、策略输入快照和确定性重放。应当移植成熟框架的**职责边界**，而不是多维护一套交易平台：

```text
数据与质量 -> 特征/状态 -> Insight（候选） -> 风险门禁 -> 人工提醒
                                    |                 |
                                    v                 v
                              episode/evidence   纸面组合（未来）
```

- `Insight` 只能表达“为什么值得复核、观察多久、何时失效”，不是买卖指令；
- 风险门禁可以阻断或降级 Insight，不能用缺数据放行；
- 真正的仓位、交易和券商执行继续在系统边界之外；
- 所有策略先进入 `shadow_only`，再经前向样本与人工批准晋级。

这借鉴了 LEAN 对 alpha、组合、风险和执行的隔离，也符合 Qlib 的版本化研究工作流，以及 NautilusTrader 的不可变事件与确定性回放理念。

## 2. 现有能力和不能越过的事实

| 领域 | 已有基础 | 仍不能声称拥有 |
| --- | --- | --- |
| 观察池实时扫描 | 腾讯同轮批量报价、同源前帧、分钟特征、日因子、精确同伴上下文；10/30 秒节奏和重点盘口轮转 | 全市场逐笔行情或完整 Level-2 |
| 微观结构 | 五档快照、深度不平衡、封单、累计量额差分和分钟资金代理，均已可作为证据 | 逐笔成交方向、委托新增/撤单事件；因此不能把现有指标称为真 OFI 或 VPIN |
| 板块/主题 | 同源的盘中资金曲线、THS 精确成员、盘后龙虎榜/涨停关系 | 用中文名称跨源拼接得到的“精确”成员或领先关系 |
| 复盘与策略验证 | episode、固定连续竞价窗口的 outcome、规则输入快照、纯规则重放 | 已完成的历史分钟回放、足量样本外胜率或已校准概率 |
| 分析师 | 文字证据、`received_at`、作者 `stated_at` 的独立复盘账本 | 可直接驱动实时加分的专家权重；目前默认为零 |

因此，盘口指标在本方案中统一叫做 **订单流代理**。Cont--Kukanov--Stoikov 的 OFI 需要最佳买卖价上的限价单、市价单和撤单事件；五档截面差分只能用于“承接/卖压的辅助证据”，不能单独触发入场。

## 3. 统一的实时状态机

每个标的在连续竞价期只能处于一个主要状态，所有状态转换都必须保存输入快照、事件时间、可用时间、来源、版本和原因码。

```text
data_blocked
    -> observe
    -> setup
    -> confirming
    -> entry_watch
    -> hold_review / reduce_review / exit_review
    -> invalidated
```

### 状态含义

| 状态 | 必要条件 | 用户可见结果 |
| --- | --- | --- |
| `data_blocked` | 行情陈旧、跨源冲突、停牌/涨跌停不可交易、午休/非连续竞价、成员映射或价格质量不足 | 只显示数据问题，不发买卖提醒 |
| `observe` | 数据合格但无结构 | 前端持续更新 |
| `setup` | 至少一种策略形态成立，但未获得时间、量能、板块或承接确认 | 前端候选，不发飞书 |
| `confirming` | 已有第二次扫描或指定确认窗证据 | 允许进入一次性待确认事件 |
| `entry_watch` | 形态、质量和风险门禁均通过 | 仅观察池发飞书；含原因、失效条件与样本门禁 |
| `hold/reduce/exit_review` | 价格/VWAP、订单流代理、板块广度中有明确支持或失效组合 | 风险复核提醒；T+1 不可卖时明确标注“风险告警，非可执行卖出” |
| `invalidated` | 结构或关键条件被破坏 | episode 关闭并记入未来结算 |

用 episode，而非固定十分钟冷却，防止同一静态极值反复打扰：同一结构只提醒一次；只有条件清除后重新出现，或价格、量能、板块广度/风险等级发生**实质升级**时才允许新 episode。

## 4. 特征架构：先做残差化与质量，不堆指标

所有特征必须登记 `FactorSpec`：版本、输入源、事件时钟、可用时钟、窗口、缺失规则、质量门槛、是否允许进入 live。计算输出需要保存数值、方向、分位数和缺失原因；禁止只落一个最终分数。

### 4.1 市场状态层（决定是否应当出手）

1. **风险状态**：指数相对 VWAP、上/下行广度、涨停/跌停扩散、全市场成交额和波动的时段标准化值。
2. **资金状态**：板块净流入的 1/5/15 分钟增量与加速度，而不是只看累积净额；必须标明东财曲线覆盖率和快照年龄。
3. **时段状态**：开盘、早盘、午后、尾盘分别独立归一化。不要把 09:35 的量和 14:30 的量用同一阈值比较。
4. **交易现实**：A 股 T+1、整手、停牌、ST/板别涨跌停和可卖数量在 `policy_gate` 前置。

输出是 `risk_on / neutral / rotation / risk_off / data_degraded`，只影响候选的允许、降级或风险预算；不直接预测涨跌。

### 4.2 板块层（确认，不替代个股）

对每一个存在**点时精确成员映射**的板块，计算：

- 相对市场的板块收益和加速度；
- 净流入增量、连续性及其在全板块横截面的分位；
- 成员中站上 VWAP 的比例、正收益比例、放量比例；
- 龙头强度：排除目标股后，Top-N 同板块成员的中位残差收益；
- 资金流突变：从显著流出转为流入、或流入快速衰竭，均需连续两帧和质量门禁。

`leader -> laggard` 只是一条研究假设。入选滞后股仍需自身价格接受、量能和风险门禁，不可以“龙头涨了”作为单独买点。

### 4.3 个股层（核心）

用“个股相对市场、相对精确板块”的残差替代绝对涨幅，避免大盘普涨时把 beta 当 alpha：

```text
residual_return_h = stock_return_h
                  - w_market * market_return_h
                  - w_sector * peer_median_return_h
```

权重先使用预先登记的简单、稳定规则或滚动稳健回归；在历史样本门禁通过前不得拟合到当天。个股特征分为：

- **价格接受**：相对 VWAP、开盘区间、前高/关键均线、回踩后维持时间；
- **动量质量**：1/3/5 分钟残差收益、收盘价在区间的位置、上涨与回撤的非对称性；
- **量能质量**：同一标的、同一分钟桶的历史基线倍数，量额单调和 VWAP 合理性；
- **相对强弱**：对指数、精确 peers、同题材龙头的残差，而非单看涨幅；
- **可交易性**：价格、涨跌停距离、换手/成交额、停牌、可卖量和数据年龄。

### 4.4 订单流代理层（仅确认或否决）

允许记录：`QI5`、买卖盘深度、单边封单、封单侵蚀、窗口化订单流代理、价格与量额背离。必须同时记录：盘口是否单边、前帧间隔、档位有效性和来源时间。

- 单边涨停/跌停盘口不能因一侧为空而丢弃；应当落 `one_sided_book`、封单量和方向；
- 前帧仅在同一交易日且间隔不超过指定阈值时参与差分；跨夜或陈旧前帧必须标记 `stale_previous`；
- 单帧符号噪声过大，研究读取侧应聚合 30 秒、1 分钟、5 分钟窗口；
- 在没有逐笔事件之前，订单流代理只可：强化 `watch`、降低确认等级、帮助解释 exit，不进入入场分数加分。

### 4.5 分析师层（弱先验而不是预测器）

分析师文本只可在 `received_at` 后可用；安强的 `stated_at` 只用于独立的作者时点复盘。将每一条文字抽为“对象、方向、期限、条件、失效条件、置信/仓位表达、可用时间、抽取版本”。

未通过统一 promotion registry 前，分析师因子只在前端显示为 `research_context`，不得改变 live 信号、飞书资格或仓位。未来即使晋级，也只作为 5--10% 上限的 context prior，且来源同步失败、抽取漂移、时间精度不足或滚动表现退化时自动归零。

## 5. 四条候选策略族

每条策略均先生成证据和 outcome，不改变已上线规则的阈值。

### A. 开盘突破后的回踩承接

**想捕捉的不是首根脉冲，而是第一段冲高后的可接受回踩。**

1. 开盘区间出现残差突破，且相对板块和至少一个龙头确认；
2. 回踩不破 VWAP/区间上沿，且在有限交易分钟内重新收回；
3. 回踩阶段缩量、重新上攻时量能恢复；
4. 板块广度不恶化、风险状态不是 `risk_off`；
5. 订单流代理只能作辅助确认；若卖压/封单侵蚀明显则降为观察。

失效是明确的：回踩后持续位于 VWAP 与区间下方、残差和板块同步转弱、或数据质量失效。标签应为“未来 15 个**交易分钟**先到目标还是先触发失效”，午休不计入时钟。

### B. 趋势中的回踩延续

适用于已有日线结构、盘中不是急拉末端的标的：价格在 VWAP 上方，短周期残差、量能质量与板块相对收益同向；回踩后不出现高量下跌。高位缩量横盘不是加仓依据，必须等重新接受确认。

### C. 下跌浪末端/B 浪反弹的承接与失败

这条策略要拆成两个方向，不能只找“抄底”：

- **反弹观察**：日线预先判定为压缩/超跌/反弹候选；盘中卖压衰竭、价格重新站回 VWAP、残差由负转正，且精确板块没有共同恶化；
- **失败减仓复核**：反弹后再失守 VWAP，同时短周期残差、资金代理或 peer 广度中至少两项失效。

它是当前 B 浪/反包研究的正确落点：将“可能反弹”记录为 setup，而不是一次性相信波浪命名。入场与失效都要记录，未来再比较“反弹成立”和“仅为下跌中继”。

### D. 板块轮动、龙头和涨停关联挖掘

1. 由板块资金**变化率**、广度和相对强弱先触发板块 episode；
2. 在精确成员中分出龙头、同步强势、低位补涨和纯跟风；
3. 涨停/连板与龙虎榜只生成次日/后续研究先验，不能倒灌为盘中订单流；
4. 目标股需要单独满足 A 或 B 的价格接受条件，才从“挖掘候选”进入观察池建议；
5. 以批量 Top20 在前端展示，禁止对非观察池股票逐只发送飞书。

## 6. 事件、提醒与前端契约

### 飞书（仅显式观察池）

每条 `confirmed` 提醒固定包含：

```text
观察时间（上海） | 策略族/版本 | 当前状态
推动证据：价格接受、残差、量能、板块/同伴、订单流代理
阻止或降级证据：数据年龄、跨源差异、风险状态、T+1/涨跌停
失效条件与复核期限 | episode 链接 | 研究门禁
```

概率契约保持严格：门禁不足时只写“历史条件基准率（未校准）”或“研究概率暂不可估”；只有样本外校准、独立日期、样本量三者均过门槛，才能显示 `P(目标先于失效 | 当时条件)`。

### 前端（全量研究候选）

前端需要把观察、挖掘和可提醒明确分层：

1. **状态矩阵**：每只观察股的 data/strategy/risk 状态与最后有效时间；
2. **板块轮动图**：增量资金曲线、覆盖率、质量和板块 episode；
3. **候选矿工**：板块 Top20、涨停关联 Top20、排除原因和加入观察池建议；
4. **证据卡**：分钟路径、VWAP、残差、量能、peer 广度、订单流代理、龙虎榜、分析师文字（分别标时间）；
5. **验证健康**：每策略的 episode、可结算数、独立交易日、样本外状态、校准状态和漂移。 

任何卡片都要区分“数据源观测”“研究假设”“已验证结果”，避免一张漂亮图把三者混为结论。

## 7. 验证、概率与反数据挖掘

### 标签与结算

不同策略必须预注册不同标签，而不是统一用次日收盘收益：

| 决策 | 标签 | 结算约束 |
| --- | --- | --- |
| entry watch | `P(未来15交易分钟目标先于失效)` | 连续竞价、价格同源、跨午休暂停计时 |
| trend hold | `P(未来30交易分钟保持VWAP/相对强势)` | 记录 MFE/MAE 与失效原因 |
| reduce/exit review | `P(未来H交易分钟先触发下行风险)` | T+1/可卖量与涨跌停可行性单独记录 |
| 板块轮动 | `P(未来15/30分钟广度与流入延续)` | 必须同一 taxonomy、同一快照口径 |

### 验证协议

1. 先积累前向、冻结的输入与 outcome；不补抓、不使用修订后数据；
2. 以完整交易日为分组，采用 purged walk-forward + embargo，禁止相邻重叠标签泄漏；
3. 首先比较可解释基线：无交易/等权、市场状态、VWAP、残差、简单量能，再比较复杂组合；
4. 只使用 OOF 预测进行 Beta/Sigmoid 校准，报告 Brier、LogLoss、ECE、可靠性图、Wilson/收缩区间；
5. 每次新增规则、参数或筛选条件都登记为一次试验；用 DSR 与 White Reality Check / SPA 类多重检验控制选择偏差；
6. 门禁至少为：60 个独立交易日、200 个独立成熟 episode、每个重要市场状态 cohort 至少 30 个；不足时保持 `descriptive_only`。

这也是为什么当前不能给实时信号填一个看似精确的“73% 胜率”：没有独立样本与校准时，那只是对已见样本的过拟合分数。

## 8. 分阶段实施清单

### Phase 0：不依赖历史数据（现在可做）

- 统一所有新特征的 `FactorSpec`、质量码和 evidence 展示；
- 对五档快照实现单边盘口、前帧时界、窗口聚合和有界清理；仍保持 attribution-only；
- 让板块 episode 以资金增量/广度变化触发，前端展示 Top20 候选和排除理由；
- 把 episode 的 clear/rearm/material-change 作为提醒去重依据；
- 每轮冻结核心规则输入，并显示前向采证、覆盖和延迟健康；
- 保持既有实时阈值不变，所有新增策略仅 `shadow_only`。

**验收**：同一冻结输入重放 hash 一致；陈旧/跨夜前帧不会生成伪订单流；候选矿工不会写入观察池或发送飞书；非连续竞价没有可结算假结果。

### Phase 1：前向影子观察（未来 60--120 日）

- 每天盘后自动结算固定期限 outcome、episode 和数据质量；
- 周度生成策略族漂移报告：触发率、确认率、数据缺口、结算覆盖、市场状态分布；
- 分析师文字仅建立 context/outcome/skill 卡，保持 live 权重为零；
- 完成候选→人工加入观察池的显式工作流，记录加入理由和加入时点。

**验收**：任一信号能从飞书/前端反查冻结输入、来源时钟和失效原因；静态极值不会重复提醒；数据源劣化有独立告警。

### Phase 2：获授权后才执行的离线验证

前提是用户单独授权可用的数据范围、存储预算和供应商预算。先做数据可用性与时钟审计，再进行以下工作：

- 历史分钟事件只按供应商 `source_available_at` 重放；
- 生成与 live 相同的特征和状态，不允许回放时访问 provider；
- 引入 A 股撮合现实（T+1、停牌、涨跌停、整手、费用、流动性滑点）；
- 做逐策略、逐市场状态和逐时段的样本外评估；
- Qlib 只作为日频因子/实验 recorder 的并行研究工具，不替换实时引擎。

**验收**：任意黄金交易日重放的状态、信号和 episode 可重复；所有收益均可追溯至合法时钟和成交可行性。

### Phase 3：受控晋级与纸面组合

- 仅门禁通过的策略生成带版本的 challenger；
- 先 `shadow -> alert-only -> paper`，每阶段固定观察窗口；
- 概率仅调节风险预算上限，永远不能覆盖硬风控；
- 引入单票、板块、相关簇、日亏、回撤、流动性和换手约束；
- 分析师权重在唯一 promotion registry 中人工批准后才可启用，并限制为 context prior。

**验收**：新 challenger 可一键回滚；滚动健康度跌破基线、数据源中断或抽取漂移时自动降为零权重/仅展示。

### Phase 4：只在 Phase 3 后的离线演化

所谓“RL/evolve”只能是离线的 champion/challenger 试验：冻结样本、固定标签与交易日切分、记录 prompt/抽取器/特征/策略版本、人工金标与成本函数。可研究 contextual bandit、概率校准和组合分配，但禁止在线用刚发生的盈亏改写盘中策略。

## 9. 数据、性能和存储预算

现有总研究空间上限 40 GiB、热库上限 28 GiB。策略挖掘按以下优先级存储：

1. 永久/长期：事件摘要、输入 hash、SignalSpec、episode、outcome、决策和质量码；
2. 有界热数据：规则最小输入快照与同源观察池报价 60--120 天（默认 90），板块曲线 60 天，盘口/秒级交叉确认更短；重复的 `suppressed/confirming` 信号只保留 90 天，且只有无投递、无 outcome 的行才可删除；
3. 不长期保存：重复 provider 原文、未使用的全量原始媒体、临时响应、过期缓存；
4. 到 80% 预警、90% 停止非必要高频采集；先减非必要 raw，再不破坏证据链。

所有新采集需要写入 retention owner、删除条件、字节预算和读路径。不得为了“可能以后有用”保留无边界 tick/raw 数据。

## 10. 不做事项

- 不将 VPIN、五档快照差分或单日资金流当成方向预测器；
- 不将涨停、龙虎榜或分析师提及直接变成买点；
- 不把 B 浪、主升浪等叙事名称替代可结算条件；
- 不在当前人工观察池上调优后宣称全市场有效；
- 不在没有 OOF 校准和门禁时展示操作概率；
- 不启动线上 RL、自动调参、自动加仓或自动下单。
