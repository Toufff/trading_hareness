# 多策略短线观察

可拆装排序因子见 [OPTIONAL_RANKING_FACTORS.md](OPTIONAL_RANKING_FACTORS.md)：默认关闭，可按用户要求给任意策略组合启用small_cap小盘偏好。不是新增策略；不改变入选条件，保留原排名、因子加分及新排名。单次变体使用独立输出目录，不覆盖正式报告。

2026-09-04。入口不是持仓过滤器，不因为账户已满仓而停止发现机会。

## 职责和数据流

```text
Longhu 既有 <=300 分页适配器
  → collect.py 增量补齐 11 个交易日（失败行业定向重试一次）
  → stock_money_flow_daily.raw.screen_snapshot（同源资金/收盘/成交额证据）
  → candidate_history.py：仅对收盘预筛候选并发补充 40~80 根严格 OHLC
  → regime.py：市场状态只路由策略优先级与研究风险预算
  → rules.py + advanced_strategies.py：九条独立筛选/行业连续广度/热度/拥挤状态
  → risk.py：与 alpha 分离的单股/行业/组合/T+1/成本/退出约束
  → selection.py：先从扫描选研究对象，再关联当日公司复核（market_events）
  → reports.py / report_parts.py：先构建九份独立报告，再构建跨策略总报告
  → service.py：统一发布同一轮报告包
  → post_close_strategy_runs.summary.strategy_lanes
  → 收盘复盘页首屏 + G:\StockPlatform\reports\short-term
```

模块位于 `quant-service/app/short_term_lanes`。没有新单体，也不接触券商。
收盘结构不用不完整的 canonical 日线拼接；旧 30 日平台筛选另外要求最近 11 个交易日完整。
历史排名只含收盘而不含 OHLC，不能把这里的收盘支撑冒称盘中最低点。
复权发生明显跳变的股票不参与连续走势计算；不伪造复权因子。

## 九条名单

| 名单 | 核心条件 | 不需要满足的条件 |
|---|---|---|
| 潜伏观察 | 5 日净流入为正，或 10 日正且最近 5 日流出较小；波动自适应的收盘区间 | 不要求每天净流入 |
| 放量启动 | 突破此前 5 日收盘高点、成交额放大、行业上涨广度 | 不强制横盘和低估值 |
| 强势回踩 | 前期相对强势、回撤缩量、未显著破坏十日结构 | 不要求回调日资金仍为正 |
| 主线趋势 | 十日相对强度、均线结构、行业中位表现和当日广度 | 不强制低位 |
| 事件机会 | 当日或近 7 日已核查的公司催化，且个股仍有相对强度和流动性 | 不把新闻标题或概念归属当作真实受益 |
| 情绪接力 | 主板接近涨停、同业有至少两只同伴、板块广度 | 不假设能买到涨停价 |
| 波动收缩突破 | 至少40根严格OHLC；真实波幅、布林带宽和成交额先缩，随后首次放量突破并有板块确认 | 不用11日收盘区间冒充OHLC收缩 |
| 板块轮动初动 | 行业近3日广度、资金、中位个股连续改善且有稳定先行股 | 不把单日行业上涨叫轮动 |
| 恐慌回收 | 急跌/假跌破被收复、抛压没有继续扩张、板块止跌且无已核验利空 | 不把继续下跌叫超跌机会 |

所有阈值集中于 `Settings`，连同版本/窗口/数据日期一起保存。
当前起始参数是研究假设，不是回测最优参数。每条名单独立排序，单行业最多展示两只；保留总匹配数。
默认成交额至少 3 亿元、换手至少 1.5%；排除 ST/退市、创业板/科创板/北交所。
2026-09-10：九策略统一研究排序为本策略/同风险状态内结构分位60%＋活跃度40%。活跃度由有效成交额75%和换手25%构成（成交额直接占30%）。有效成交额取当日与最近5日中位数的几何均值；不足3日只按当日半额计分并明确数据缺口。成交额对数平滑至10亿元封顶，不能直接按大市值排名。结构匹配和风险状态仍先于排序，不因成交额大而放宽。高级策略OHLC预筛使用同一活跃排序，避免低成交额候选消耗补数容量。报告逐股显示成交额历史及评分依据。详见 [成交额排序验收](SHORT_TERM_LIQUIDITY_AUDIT_20260910.md)。
近十日涨幅过大或成交额骤增列为高拥挤；资金累计正但当日放量下跌列为转弱。保留名单，不混进优先低吸观察。

## 调用和部署

在已加载 `runtime.env` 的环境中：

```powershell
cd G:\StockPlatform\current\quant-service
..\.venv\Scripts\python.exe -m app.short_term_lanes.service --date YYYY-MM-DD --collect --output-dir G:\StockPlatform\reports\short-term
```

上面的直接 CLI 扫描是独立研究用法，不得拿其输出与随后重新执行的 API 扫描当作同轮结果。
正式 Windows `run-post-close-pipeline.ps1` 先更新行情，使用 `--collect-only` 补输入，不扫描/写报告；仅由既有 `POST /api/v1/strategy/post-close/run` 扫描一次并保存。随后 `export-strategy-publication.py` 按预期 run_id、日期与完整输入/正文哈希导出已落库结果，最后严格比对本地 JSON、十份正文、owner 与 dashboard。导出不调用模型、不重新计算策略。发布失败保存具体 failed checks 与差异字段路径，不能忽略消息年龄或截止时间差异来放宽验收。
只有同日期同版本、九名单完成且报告文件/owner API/网页 API 的报告包一致才跳过；行情已落库不再等于任务完成。缺失或损坏任一报告会重新生成，不因数据库状态为 completed 而跳过。
使用现有静默任务宿主，不创建前台窗口。

公司复核：`--review-file file.json`，每条包含 symbol/name/business/risk/conclusion/sources（url/published_date），可选 catalyst。新增记录必须有 selection：origin（scan/user_followup/risk/background）、why_now、question、disposition（retain_watch/downgrade_watch/exclude）；用户指定还必须有 request_reference。缺少选取理由的旧记录仍可读取，但不追认成优先复核。
接受交易所/巨潮一手公告、法定披露报刊以及明确标识的公司公告全文镜像，拒绝未来日期。这是人工或模型实际审阅后的输入接口，不是自动确认新闻真实。未核查的原始新闻不能升级为公司利好。

研究对象先于已有研究记录选取：每条非空策略优先取展示第1的代表并跨策略去重；保留实际策略、展示顺位、匹配总数、量价依据、下一展示候选对照、日期/版本/证据哈希。展示順位不是全市场总排名，同一股票跨策略入选也不是独立利好计票。
报告和页面共同消费 review_plan/review_groups/review_coverage：优先代表、补充候选、用户指定、风险案例、折叠背景资料分开。每条非空策略按 `selected -> observation_list -> caution_list` 取首位作为最低覆盖，不再因市场路由把候选转成结构观察就断掉研究。首位覆盖不是研究上限：推荐池续审、用户跟踪及同类比较可以增加实际复核数量。推荐决策已完成的公司研究必须回写同一证据账本并重新生成同轮策略报告，不得在一份报告中已研究、另一份报告仍声称“未复核”。
这是公司证据复核覆盖，不是完整买入授权。扫描与公司研究分别计数；事件为空时检查已核验事件覆盖数，不宣称全市场没有利好。

2026-09-10：资金3/5/10日、横盘5/8/10日容错规则已迁入 accumulation_rules；完整交集与接近条件保留在 accumulation_observations，两个单条件附录位于独立报告末尾。旧研究与生命周期事件迁入G盘 legacy_source_records，带原始日期可查询；生命周期自动承接尚须单独验收，不能以导入成功代替。

## 独立报告与总报告

### 往期候选跟踪（2026-09-11）

`tracking_rules.py`计算描述性后续表现，`tracking_repository.py`持久化，`tracking_report.py`及`ObservationFollowup.vue`分别展示同轮数据。G盘两张追加式表`strategy_observation_origins`与`strategy_observation_evaluations`保存原始观察和逐日评价；最新扫描覆盖不会删除旧样本。原始日期、策略版本、配置、市值加分、展示排名、理由、原确认/失效文字及公司复核冻结保存；不同版本不混成一条实盘胜率。

新扫描保存每个策略全部匹配，不只前5；仍有匹配但退出首屏、涨停、跌停都继续保留。每次收盘同时刷新最近60自然日发现记录的第1/3/5/10交易日表现，十日完成后长期留档。缺交易日行情不跳过，未到期不填0。交易日用交易日历，不根据某股票缺行情推迟评价日。

原有数据库扫描可回填为`reconstructed`，保留原记录而不是重跑历史参数。补录没有原始推荐条件的口头消息不得伪造。盘中人工首选与收盘程序排名是不同来源；原公司研究意见另存，不覆盖机械扫描条件。

收益字段只是相对发现日收盘的观察涨跌，记录后续日线高低、资金及涨跌停状态，不是订单收益。上下参考线同日都触及时标记先后未知；日线不能确认缩量回踩、持续站稳、VWAP或涨停可买性，因此实际成交状态始终未验证。此账本为后续改进提供完整正负样本，不自动提升策略成熟度。

跟踪失败单独给出`followup.status=failed`及`observation_tracking_failed`日志，不阻断今日独立扫描，也不能把扫描成功叫作跟踪成功。真实验收入口`scripts/verify-observation-followup-live.py`，输出到独立研究目录；不把验收扫描当作官网正式九策略发布。

每次生成 **九份策略独立报告 + 一份总报告 + 一个 JSON 报告包**，全部来自同一次数据快照。基础六策略共享全市场11日快照；高级策略只对最多96只预筛候选补充严格OHLC，不能把这个范围冒充全市场OHLC覆盖。

- 独立报告：`YYYY-MM-DD_strategy_<key>.md`，包含策略目的、数据日期/覆盖、为什么选取研究对象、公司证据及结论、本策略候选的量价/确认/放弃条件。只保留该策略候选和风险观察中的公司记录；研究事实可复用，其他策略名次和结论不能串入。首位研究覆盖与展示候选研究覆盖分别列出。
- 总报告：保留 `YYYY-MM-DD_short_term_lanes.md` 旧链接，先给研究结论，再做策略比较、跨策略去重/分歧说明、候选索引；链接到各策略报告，不再重复拼接六份候选详情。
- 面向人的“本次结论”只展示已完成公司比较的股票；其余量价/结构筛选观察集中放在独立报告的下方明细，不逐股填充“未复核”占位文案，也不因移出结论区而丢失原始筛选证据。
- 空策略也有报告：区分没有匹配与数据不足，事件策略同时说明已核验事件覆盖。不能把空名单解释为该方向全市场没有机会。
- `report_bundle` 保存十个正文、文件名、日期、输入哈希及正文哈希，随既有 `strategy_lanes` JSONB 落库；无需新接口或新数据库。逐文件原子替换，JSON 最后写入，回读校验可发现缺失/混代文件。
- 网页“收盘复盘 → 多策略短线报告”提供总报告和九个独立入口，每次只展开一份；可下载当前报告的原始 Markdown，不在浏览器重新推导报告。
- 生成验收 `--reports-only` 只证明文件/接口发布一致，不声称公司研究和盈利有效。完整验收另检查优先研究覆盖。

## 验收与边界

1. 真实 Longhu 请求每页不超过 300；逐日齐全，同源资金口径不混用。
2. 回归：缺日、未来数据、复权跳变、低流动性、ST/板块过滤、放量下跌、过热、重复执行。
3. 同日 POST → PostgreSQL → GET → 前端一致；报告能显示名称、成交额、确认/放弃条件。
   `scripts/verify-short-term-lanes.py` 另验：研究计划独立于已有报告、首位代表覆盖、选取理由和核查问题可见、来源分组互斥、研究结论先于原始名单。缺少代表复核时验收明确失败，而不是用扫描 completed 冒充研究完成。
   浏览器必须在数据加载前打开页面、等待新数据并再次刷新：不能仅验证 HTTP 响应。2026-09-04 实测发现三个页签展开 `proxyRefs` 时冻结了初始值，已改为保留属性引用并加入迟到数据回归测试。
   确认条件区分已经突破和等待突破；启动、趋势、回踩、接力使用各自失效条件，不统一套用远处历史低点。
4. 新模块均为 research-only，无自动买入授权，不继承历史负收益策略的“成熟”标签。
5. 当前验收只能证明采集、分组和展示按规则运作，不能证明盈利。后续评价必须逐名单、下一交易日可成交时间、计入费用/T+1/涨跌停和样本外数据，不能用当天收盘成交回测冒充可执行收益。

设计参考：沿用 [Qlib](https://github.com/microsoft/qlib) 的信号/策略/执行分层与 [vn.py](https://github.com/vnpy/vnpy) 的策略状态/回放分离思想；没有照搬未经 A 股市场约束检验的盈利参数。
