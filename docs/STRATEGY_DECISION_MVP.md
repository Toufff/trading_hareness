# 多源盘中/复盘决策 MVP

`POST /api/v1/strategy/decisions/run` 生成一份可复现的研究候选快照；它不会交易，也不会把公开实时行情标记为可自动下单。

```json
{
  "session": "intraday",
  "kind": "all",
  "limit": 20,
  "validate_tushare_realtime": true
}
```

用 `GET /api/v1/strategy/decisions/latest` 读取最近一次该模型版本的运行及候选。每次运行都会写入既有的 `recommendation_runs` 与 `recommendations`，保留原始分数、风险标记、板块映射覆盖率、数据源状态和失效条件。

## 信号边界

| 层级 | 数据 | 作用 | 时间边界 |
| --- | --- | --- | --- |
| 市场状态 | 东财行业/概念板块资金流 | 以同一 taxonomy 内横截面排名判定 risk-on / neutral / risk-off | 盘中快照 |
| 板块到个股 | 已同步的东财板块成员 + 腾讯全 A 即时行情 | 板块资金、个股主力净流、量比、换手、涨跌幅生成候选 | 只对有精确成员映射的板块生效 |
| 实时复核 | 超级源 `rt_k` | 最多复核前三个候选，不做全市场扫描 | 仅连续竞价；不可用时明确 `skipped` |
| 盘后背景 | Tushare 日频资金流、THS 行业/概念流、龙虎榜、涨停池 | 为下一交易日研究提供上下文 | 不参与当日盘中分数 |
| 补充证据 | AKShare（东财龙虎榜/资金流、涨停池、市场宽度）、巨潮公告 | 记录可得性、事件和交叉验证结果 | 公开源，默认不提升为自动交易依据 |
| 机构源 | 新华财经 | 预留为受合同约束的数据/API 流 | 需要 URL、鉴权方式及字段契约后才启用 |

## 风险门禁

- 任何板块成员映射不完整都会写入 `incomplete_board_mapping`；输出覆盖率而不是虚构“全板块 top10”。
- 策略运行可对每个 taxonomy 最多补齐 3 个资金流靠前、尚未映射的东财板块；成分查询有 12 秒硬预算，实时流与腾讯横截面各有 20 秒预算。失败只降低覆盖率，不阻塞或无限等待盘中快照。
- 个股或板块主力净流入非正时为 `no_trade`；高涨幅扩张（>= 8%）与极高换手（>= 25%）均标明风险，不会进入盘中 `research_candidate`。
- `龙虎榜`、完整涨停池和日频资金流仅写进 `post_close_context`。查询条件强制 `available_at <= observed_at`，防止未来数据泄漏。
- 当前公共实时源不具备完整授权全市场实时行情的质量保证，因此 `decision_eligible` 固定为 `false`。候选仅用于研究、复盘和人工确认。
- 每次运行会把 AKShare、东财、腾讯、Tushare 的能力健康记录和盘后事件库存写入 `source_status`；新华财经在未配置时明确显示为 `not_configured`，不会被伪装成失效或实时数据源。

## 运行节奏

1. 09:35 后、10:30、13:30、14:30 生成盘中快照；只比较同一快照内的相对强弱。
2. 15:10 后同步/核验日频、板块流、龙虎榜和事件，运行 `session: "close"` 作为下一交易日的观察池。
3. 每个交易日回填 `outcomes`，按 `run_id` 做 walk-forward 统计；未积累足够样本前，禁止提升为自动化策略。

这是一个执行与评估骨架，而非收益承诺。要提升到可交易级别，仍需完成全量同源板块成员映射、受许可的全市场实时行情、连续多日稳定性测试和样本外回测。
